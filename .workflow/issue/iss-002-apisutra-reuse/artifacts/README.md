# Проверки аудита ApiSutra

Из корня MaxSutra после `composer install`:

```bash
php .workflow/audit/aud-001-apisutra-reuse/artifacts/probe.php
```

Сохранённый запуск: [observations.json](observations.json).
Сценарии и обычные readonly DTO находятся в [probe.php](probe.php) и `fixtures/`.
Вспомогательные классы этого приложения аудита загружаются явно; они не входят
в PSR-4 пакета и не добавляют ещё один постоянный набор тестов в composer test.

Проверяется закреплённая в lock-файле версия. Скрипт печатает фактический reference
зависимости и завершается ненулевым кодом, если наблюдаемое поведение изменилось.
При новой версии расхождение нужно разобрать, а не автоматически обновлять ожидания.

Проверки используют RecordingHttpClient MaxSutra под HttpTransport ApiSutra,
один сценарий штатного fake и локальные счётчики квот с немедленным отказом.
Внешней сети, настоящих токенов, Redis и ожидания окна квоты нет.
Все поля и ответы синтетические. HTTP-статусы ошибок и необязательные значения
проверяются как контракт, не как подтверждение работы внешнего API.

P01–P21 фиксируют как возможности, так и разрывы с требуемым поведением.
Успешный запуск не означает, что все пожелания из
[задания разработчику](../upstream-requirements.md) уже реализованы.
