# Контракт изоляции значений metadata cache

- Дата создания: 2026-09-14
- Дата обновления: 2026-09-14

Основание — [план 031](pln-031-readme.md) и CR-01 из
[metadata-review](../../discussion/dsc-005-declarative-dto-contracts/metadata-review.md).
Решение владельца пакета от 2026-09-14: значения из выражений `new` следуют
семантике прямого вызова PHP, а не повторяют полное вычисление деклараций при
выключенном кеше. Публичные сигнатуры не меняются, поэтому отдельный ADR не нужен:
изменение наблюдаемого поведения описывается в changelog и документации.

## Принцип

Metadata cache хранит сведения о декларации: reflection-объекты, имена, флаги,
`ReflectionAttribute` и экземпляры атрибутов, которые содержат только значения.
Значение, созданное выражением `new`, не хранится в кеше как готовый объект и не
передаётся двум узлам преобразования. Результат и число вычислений выражений
одинаковы при включённом и выключенном кеше.

Значениями считаются scalar, null, enum case и массивы из них на любой глубине.
Любой другой объект, включая closure, считается изменяемым значением.

## Defaults параметров конструктора

| Ситуация | Поведение |
| --- | --- |
| Значение для параметра разрешено (включая явный null) | Передаётся именованным аргументом; выражение default не вычисляется |
| Значения нет, у параметра есть default | Аргумент не передаётся; PHP вычисляет default при вызове конструктора, ровно один раз на созданный DTO |
| Значения нет, default отсутствует | `required_field_missing`, как сейчас |
| Variadic-параметр без значения | Не передаётся, как сейчас |

- Metadata хранит только признак наличия default. `ReflectionParameter::getDefaultValue()`
  для построения аргументов не вызывается ни при построении, ни при чтении кеша.
- Правило одинаково для constructor-first пути (`newInstanceArgs`) и пути
  с последующим заполнением свойств (`invokeArgs`). Оба используют именованные аргументы.
- Массив с объектами в default (`[new Counter()]`) вычисляется PHP заново
  для каждого DTO, так же как одиночный объект.
- Исключение из выражения default выходит из вызова конструктора так же, как
  исключение самого конструктора сейчас. Отдельного reason не вводится.
- Scalar/enum/array defaults дают прежние значения. Порядок проверки обязательных
  параметров и типов аргументов не меняется.

## Экземпляры атрибутов

Правило действует для атрибутов, которые читают Hydrator (`:hydrator`),
DtoSerializer (`:dto-serializer`) и RequestPartsCollector (`:serializer`).

| Экземпляр атрибута | Кеш хранит | На каждое применение |
| --- | --- | --- |
| Все свойства экземпляра — значения | Экземпляр и `ReflectionAttribute` | Переиспользуется тот же экземпляр |
| Хотя бы одно свойство содержит объект на любой глубине | Только `ReflectionAttribute` и признак | Новый экземпляр через `ReflectionAttribute::newInstance()` |

- Признак определяется по первому созданному экземпляру: проверяются все его свойства,
  а не только публичные. Этот первый экземпляр используется для первого применения;
  лишнего вычисления аргументов нет.
- Применение — обработка одного свойства одного узла: одного создаваемого DTO
  в Hydrator, одного сериализуемого DTO в DtoSerializer, одного request в
  RequestPartsCollector. Все атрибуты свойства в одном применении берутся из одной
  материализации; элементы одной коллекции — разные применения.
- Cast-обработчик по-прежнему создаётся на каждое применение и получает аргументы
  только что созданного экземпляра атрибута. `DefaultValue.value` возвращается из
  экземпляра текущего применения.
- Атрибуты без объектов (типичные `From`, `Map`, `Nested`, `Cast` со scalar-аргументами)
  не создаются повторно. Сохранение стоимости прогретого кеша проверяется критериями
  P01–P04 [приёмки](acceptance.md#стоимость).

## Границы

- Не изолируются автоматически объекты, которые передал вызывающий код: входной payload,
  экземпляры casts профиля и `ClientConfig`, статическое состояние обработчиков,
  готовые DTO. Их семантика общего объекта остаётся явной.
- Жизненный цикл `Nested.itemCast` (один экземпляр на проход списка) не меняется;
  аргументы у itemCast отсутствуют.
- Набор частей запроса, где применяется Cast, не меняется: body, BodyRoot и query
  его вызывают, header, path и file — нет.
- `AttributeRegistry` и `AttributeMetadataCache::warmup` уже хранят
  `ReflectionAttribute`; их подход не меняется.
- Кеш `RequestSpec`, `RequestDefaults` и резолверы профилей проверяются на этапе 2.
  `RequestDefaults` содержит только enum. Если в другом кеше найдётся экземпляр
  атрибута с объектом, к нему применяется то же правило в объёме 031.
- Отключение кеша, поверхностный `clone`, `serialize/unserialize` и глубокое
  копирование payload не используются как исправление.

## Изменения наблюдаемого поведения

| До 031 | После 031 |
| --- | --- |
| Cache on: один объект default на все DTO клиента | Новый объект на каждый DTO, где значение не пришло |
| Cache off: default вычисляется для каждого параметра каждого узла, даже если значение пришло | Только когда значение не пришло |
| Cache on: объект в аргументах атрибута общий для всех применений | Новый экземпляр атрибута на применение |
| `DTO::from()` и клиент в Production ведут себя по-разному | Одинаково |

Число вызовов конструкторов объектов из выражений default уменьшается там, где
значение приходит из данных. Это документируется как исправление без новых настроек.
