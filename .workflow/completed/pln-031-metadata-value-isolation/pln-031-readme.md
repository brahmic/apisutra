# Изоляция значений в metadata cache гидратора и сериализаторов

- Дата создания: 2026-09-14
- Дата обновления: 2026-09-14
- Статус: завершён

## Основание, приоритет и цель

Основание — CR-01 из [третьего разбора](../../discussion/dsc-005-declarative-dto-contracts/clarification-review.md#cr-01-объектный-default-разделяется-при-включённом-metadata-cache)
и [проверка его полной области](../../discussion/dsc-005-declarative-dto-contracts/metadata-review.md).
Приоритет повышен до **P1**: дефект действует в обычной конфигурации клиента,
затрагивает входящие DTO и исходящий payload, удерживает изменяемое состояние
между независимыми операциями одного клиента. Внешние правила 028 и await не нужны.

Причина — сохранение вычисленных объектных значений в кеше описаний. Readonly
атрибут/DTO не делает неизменяемым вложенный объект. Default окружения ClientConfig
— Production; кеш клиента выключен только в Local/Testing. Без объектных значений
в рассматриваемых декларациях переноса изменяемого состояния не воспроизведено.

Цель — metadata cache сохраняет стоимость повторного поиска деклараций, но не
превращает созданные через `new` значения в общие между DTO/операциями объекты.
Результаты не должны зависеть от прогрева кеша и порядка вызовов. Исправление
не требует Laravel, новых внешних правил или изменения continuation-протокола.

## Подтверждённая область

База — `eeb0b6a6154f8f95799be08f1389b799b19a6c24`, PHP 8.4.15.

| Декларация / вход | Наблюдение при cache on | Контроль cache off |
| --- | --- | --- |
| Constructor default `new MutableCounter()` | Объект общий для двух DTO | Независимые объекты |
| Constructor default `[new MutableCounter()]` | Массивы содержат один объект | Независимые вложенные объекты |
| DefaultValue(value: [new MutableCounter()]) | Изменение первого DTO видно во втором | Во втором исходное значение |
| Cast с объектным аргументом, hydrate | Счётчик [1, 2] | [1, 1] |
| Тот же Cast, DtoSerializer::serialize | [1, 2] | [1, 1] |
| Тот же Cast, query через Serializer/RequestPartsCollector | [1, 2] | [1, 1] |
| Cast вложенного wire DTO через Serializer | [1, 2] | [1, 1] |
| Returns → элементы пагинации → итог CompositeFlow, один клиент | Изменение одного state видно на всех трёх входах; два элемента страницы разделяют state | Local/Testing дают независимые объекты |
| DTO::from() | Независимые объекты через default() без кеша | Отличается от клиента с окружением по умолчанию |
| Повторный resolve клиента из ClientRegistry | Состояние сохранено после удаления ссылки на первый DTO | Новый клиент имеет независимый кеш |

У кастов создаются **новые экземпляры обработчика**, но им передаётся один
объектный аргумент из кешированного атрибута. Исправить только создание обработчика
или constructor defaults DTO недостаточно.

ClientRegistry удерживает клиентов, SdkServiceProvider регистрирует его через
singletonIf. При повторном использовании этого контейнера/клиента в worker
состояние может перейти между заданиями или пользователями. Probe воспроизводит
удержание клиента реестром в одном процессе; реальный Laravel worker и изоляция
пользователей приложения не запускались. Это условный риск, не утверждение
о состоявшейся утечке и не о глобальном разделении между всеми клиентами.

## Граница исправления и зависимостей

В объём входят три производных metadata-кеша:

- Hydrator, ключ `:hydrator`: constructor defaults и экземпляры атрибутов поля,
  прежде всего Cast.args и DefaultValue.value с объектами внутри массивов;
- DtoSerializer, ключ `:dto-serializer`: экземпляры атрибутов и их объектные args;
- RequestPartsCollector, ключ `:serializer`: те же args при сборке частей запроса;
  проверить вызов вложенного DtoSerializer через публичный Serializer.

Проследить общую ReflectionHelperTrait и все поля этих metadata, чтобы объект
не оставался скрыт в массиве после исправления только верхнего уровня. Проверить
AttributeRegistry/AttributeMetadataCache::warmup: они уже сохраняют ReflectionAttribute,
а не его экземпляр; не менять этот подход без обнаруженного нарушения. Классовые
policy/profile резолверы, RequestDefaults и собственный кеш RequestSpec сверить
на границе, не объявляя их дефектными только по наличию кеширования.

Явно переданные пользователем общие объекты, registry/profile casts, статическое
состояние пользовательских обработчиков и жизненный цикл Nested.itemCast не
изолируются этим исправлением автоматически. В 028 В04 отдельно выбираются scope
и срок жизни обработчиков. Не отключать metadata cache целиком; это возможный
диагностический обход, а не целевой результат. Не заменять вычисление выражения
поверхностным clone или сериализацией произвольного объекта.

031 не зависит от 028/030 и должен исправить текущие клиентские пути самостоятельно.
[030](../pln-030-continuation-errors/pln-030-readme.md) сохраняет Pending/Ready,
ошибки и передачу гидратора; его подключение кеширующего гидратора и завершение
ждут реализации 031. Контракты 030 можно выбирать раньше. В
[028](../pln-028-declarative-dto/pln-028-readme.md) общий metadata cache опирается
на исправление 031, await-интеграция — на завершённый 030. План 027 отложен отдельно.

## Вопросы, закрытые контрактом

Таблица сохраняет исходную постановку; принятые ответы — в contracts.md:

| Вопрос | Рекомендуемый контракт / что требуется уточнить |
| --- | --- |
| Constructor default, включая массивы с объектами | Новое вычисление выражения для создаваемого DTO; не общий прототип |
| Cast.args / DefaultValue.value | Материализовать декларацию заново для очередного узла DTO/запроса; вложенные объекты не переиспользуются из metadata |
| Повторное посещение узла, коллекции и рекурсия | Определить границу вызова явно; независимость между элементами и между преобразованиями, без дублирования вызова DTO-конструктора |
| Неиспользованное значение default / атрибут поля | Зафиксировать, когда выполняется выражение и возможный пользовательский конструктор, особенно при присутствующем значении/skip/null; не менять число побочных вызовов неоговорённо |
| Неизменяемые значения | Сохранить scalar/null, enum и обычные массивы, порядок разрешения атрибутов/профиля |
| Ошибки вычисления выражения | Зафиксировать момент и прежнюю границу доставки исключения; не смешивать с Pending/Ready 030 |
| Общий объект от вызывающего кода | Сохранять его явную семантику; не вводить универсальное глубокое копирование всего payload |
| Стоимость кеша и пересоздания | Выбрать пересоздание всех деклараций либо только нуждающихся в нём; подтвердить сохранение кеша поиска и измерить цену исправления. Выборочная оптимизация не должна добавлять пробный `new`, дублировать побочные вызовы или менять доставку ошибок |

Публичные сигнатуры и режимы не должны расширяться ради исправления. Если выбранный
контракт потребует нового публичного поведения сверх устранения разделения значений,
его основание оформить ADR по фактическому решению. Принятый контракт публичное
поведение не расширяет, поэтому ADR не требуется.

### Как проверить стоимость

Сохранение выгоды кеша требует отдельной приёмки, а не вывода из наличия cache->get.
До реализации зафиксировать метод измерения и допустимые изменения в acceptance.md:

- структурная проверка: прогретый кеш повторно использует найденные описания класса;
  повторные объекты/элементы не запускают полный поиск свойств, параметров и атрибутов.
  Счётчики поиска и создания значений разделены: необходимое вычисление `new`
  не считается промахом metadata cache;
- воспроизводимое измерение для каждого из трёх преобразователей: отдельно DTO/запрос
  без объектных деклараций и с ними, одиночные/повторные вызовы и коллекция;
  сравнить исходную и исправленную версии при cache on/off, холодный и прогретый режимы;
- сохранить версии PHP, настройки OPcache/JIT, входы, число итераций, повторные
  измерения времени и памяти. Для пути без объектных деклараций оценить регрессию
  относительно прежнего прогретого кеша; для объектного пути отдельно учитывать
  обязательные новые объекты, отсутствовавшие в дефектной версии;
- критерии принятия: повторный поиск действительно устранён, metadata не удерживает
  значения прошлых операций, преимущество прогретого кеша подтверждено на выбранной
  повторной нагрузке; допустимую регрессию времени/памяти определить по baseline и
  разбросу измерений. Произвольный процент или таймер в обычном unit-тесте не вводить.

Контракт выбрал избирательное пересоздание: признак объектов берётся из первого
экземпляра атрибута, без дополнительного вычисления выражения. Метод и baseline
дефектной версии сохранены ([cost-baseline.json](artifacts/cost-baseline.json)),
критерии P01–P04 — в [acceptance.md](acceptance.md#стоимость). Отсутствие регрессии
будет доказано только сравнением на одной машине после реализации.
