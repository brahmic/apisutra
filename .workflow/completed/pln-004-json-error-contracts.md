# Строгий JSON и корректная классификация ошибок

- Дата создания: 2026-09-12
- Дата обновления: 2026-09-12
- Статус: завершён

## Цель и основание

Приоритетная часть AS-07/AS-02 из [issue/001](../issue/001/technical-specification.md),
согласованная пользователем после [pln-003](../completed/pln-003-automatic-cache-identity.md).
Ошибочный JSON не должен превращаться в пустое тело/успех, а HTTP-ошибки и ошибки
программного кода — в connection_failed. Исходная версия: da8bd21.

## Объём

1. Строгое кодирование исходящего JSON, включая JSON-поля multipart/base64 и JsonCast;
   типизированная serialization error до HTTP, исходная причина в previous.
2. Строгий разбор успешных JSON-ответов, сохранение HTTP-контекста ошибки разбора.
   Согласованный контракт без DTO: null/пустое тело/204 → null, text/plain → строка;
   непустой ответ без Content-Type разбирается как JSON.
   Download и обработчики расширений сохраняют собственные форматы.
3. Нормализация известных PSR-18 сетевых/транспортных исключений до retry; подтверждённый
   timeout определяется по типу/metadata, не тексту. Произвольные Throwable не становятся
   сетевыми. Сохранить явно настроенные классы исключений для retry.
4. После последней попытки с HTTP-ответом вернуть его в штатный error mapping;
   ошибки 4xx не обозначать server_error. Сетевая ошибка последней попытки не должна
   использовать HTTP-контекст предыдущей попытки.
5. Различать serialization, response decoding, hydration, hook, configuration и
   неизвестную ошибку исполнения; сохранить result-first/throwOnErrors/control-flow.
6. Регрессии, полный прогон, профильные guides и changelog.

## Границы

Полный AS-07 (новые политики больших чисел, строгий unwrap, все nullable DTO-контракты),
безопасность retry для операций/потоков, backoff/deadline redesign AS-03/08 и полноценный
async не входят. Существующие provider error hooks и расширения сохраняются.

## Приёмка

Невалидный UTF-8/INF/NAN и неподдерживаемый JSON не отправляются. Malformed JSON
не даёт успех; HTTP 503 с HTML сохраняет HTTP-ошибку. Сетевая ошибка → успех работает
при разрешённом retry GET. Последовательности network → HTTP и HTTP → network
описывают последнюю попытку. Ошибки hook/DTO не повторяются как сетевые.
Проверить raw/resolved/dataOrFail, throwOnErrors, async promise и batch, сохранение
false/пустого списка и отдельного query, download и обработчиков расширений.

## Реализованная часть и проверки

Ошибки JSON-кодирования теперь типизированы; циклы массивов и DTO останавливаются
до HTTP. Добавлен явный ProviderResponse::jsonStrict(); pipeline проверяет непустые
JSON-ответы с учётом download/extension веток и сохраняет скалярные значения. Переписаны нормализация исключений до
retry и возврат последнего HTTP-ответа. HTTP-ошибки не требуют валидного JSON body.
Сохраняются исходные объекты исключений hooks и control-flow; их классификация
отделена от транспорта. В частности, EarlyReturn на AfterResponse теперь соответствует
документированному успеху, а не прежнему ошибочному connection_failed.

Первый прогон новых воспроизводящих тестов: 18 падений, 4 успешных теста.
После исправлений и расширения проверки:

- `composer test -- --compact`: 875 тестов, 2484 assertions; без падений,
  38 тестов с deprecation, 6.00 s, PHP 8.5.4.
- `composer dump-autoload --optimize --strict-psr`: успешно, 4882 класса.
- Синтаксис изменённых/новых PHP-файлов и относительные Markdown-ссылки проверены.
- `git diff --check`: успешно.
- [Standalone JSON smoke](../../tests/Support/standalone-json-smoke.php) выполнен
  в отдельной копии с установленными --no-dev зависимостями: HTTP-клиент PSR-18,
  нормализация network failure/retry, ошибка сериализации до отправки и malformed
  JSON с сохранением HTTP 200, успешные null/text/false. Illuminate и Guzzle HTTP Client отсутствуют.

Старые тесты, закреплявшие ошибочную классификацию, приведены к исправленному
контракту. В тесте typed error context исправлена неправильная mock-фикстура:
обычный массив payload заменён явным HTTP 500 MockResponse.
Composer.lock, версия пакета и исходные материалы issue/001 не менялись.

## Согласованное решение и завершение

2026-09-12 пользователь подтвердил в переписке: «Да, применить предложенный контракт».
Успех без DTO: JSON null → null; HTTP 204/пустое тело → null; text/plain → исходная
строка; непустой ответ без Content-Type → строгий JSON. false/0/строки также сохраняются.
Array-only BeforeHydrate вызывается для массивов; AfterResponse/AfterHydrate сохраняются
для любого успеха. Пустой ввод DTO по-прежнему гидратируется из пустого набора полей.
Download получает байты; выбранный handler расширения сохраняет собственный формат.

Регрессии проверяют sync/promise, raw/resolved/dataOrFail, MIME с параметрами,
отсутствующий Content-Type, пустое тело, 204, malformed JSON, hooks, DTO и download/handlers.
[Публичный контракт](../../docs/guides/client-config/responses-errors.md#успешный-ответ-без-dto),
[ошибки](../../docs/guides/errors.md), [hooks](../../docs/guides/hooks.md) и changelog обновлены.
Критерии выбранного объёма выполнены. Полные AS-07/AS-02 и остальные задачи issue/001
не объявляются закрытыми этим планом; границы выше сохраняются.
