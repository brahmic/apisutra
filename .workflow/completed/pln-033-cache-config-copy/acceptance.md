# Приёмка AS-6: разделение cacheStore и параметров

Матрица проверяет [контракт](contracts.md), принятый 2026-09-15 по
[K03](questions.md#k03-разделение-api-и-миграция) и ADR-004, а также
[миграцию](migration.md). Прежняя редакция C01–C20 для совместимой нормализации
заменена этой матрицей C01–C26. Реализация принята; [соответствие тестам и результаты](implementation.md).

## Создание и копирование

| ID | Сценарий | Проверка |
| --- | --- | --- |
| C01 | Оба null, только store, только параметры, оба аргумента | Публичная пара cacheStore/cacheConfig точно по контракту; настройки без store допустимы; defaults не записываются вместо public null |
| C02 | Каждая форма → with() | Новый ClientConfig, исходные поля и ссылки сохранены |
| C03 | Каждая форма → with(timeout:7), перенесённые U13–U14 | Store и параметры сохранены, оригинал не меняется |
| C04 | Полный P: ttl/prefix/mode/identity/locks; замена store, повторные копии | Прежний P и зависимости по ссылке, все поля сохранены; без клонирования/вызовов методов |
| C05 | Замена cacheConfig на новый P с ttl 10 вместо 60, перенос U06 | P2 применён по ссылке, store прежний; новые параметры не игнорируются |
| C06 | Новый P задаёт только ttl; ранее нестандартные prefix/mode/identity/locks | Остальные параметры берутся из defaults нового блока; глубокого слияния нет |
| C07 | Смена только store; смена S/P одновременно; последовательные смены в разном порядке | Только указанные поля меняются; независимые операции дают ту же пару ссылок |
| C08 | cacheConfig:null, в том числе после Disabled, отдельно и вместе с cacheStore:S2 | Store сохранён/явно заменён, public cacheConfig=null; HTTP defaults могут снова разрешить кеш |
| C09 | cacheStore:null при полном P; затем with(), смена timeout/параметров и request Enabled | Store остаётся null; параметры его не восстанавливают; P и явно заданный locks не сброшены |
| C10 | Оба null; null store + новый P; новый store + null P; перенос намерений U07–U09 | Каждое поле независимо, backend не очищен; старый синтаксис не используется |
| C11 | cache: в конструкторе/with/unpacking/fromLaravel, также вместе с cacheStore; CacheConfig(store:...); неправильные типы | Неизвестные именованные аргументы дают PHP Error, неверные типы — TypeError; до HTTP; никакого игнорирования/алиаса; текст движка не фиксируется |
| C12 | with(auth:null), with(retry:...), with(hydrationRules:null), массивы и прочие поля | Прежние семантика полной замены и явный null сохраняются |

## Наблюдаемое выполнение

| ID | Сценарий | Проверка |
| --- | --- | --- |
| C13 | Два одинаковых GET до/после чистой копии и смены timeout для перенесённых способов подключения | Один HTTP на новую пару в пустом store; копия использует запись исходного клиента при тех же S/P |
| C14 | Смена ttl 60 → 10; fake clock и новые записи | Старый клиент сохраняет свою политику; новые записи копии истекают по новому TTL; прежние записи не получают новый срок автоматически |
| C15 | Независимая смена store, prefix/identity и их комбинация | Выбранные backend/пространства верны; исходный клиент остаётся на прежних |
| C16 | HTTP + TokenAuthenticator, с P и без него, затем with(timeout); известная и отсутствующая auth identity | Обе подсистемы получают один cacheStore; общая/локальная область по прежним правилам; нет лишнего получения токена при допустимом общем кеше |
| C17 | Disabled/ReadOnly/WriteOnly, withoutCache и overrides/атрибуты запроса | Прежние приоритеты чтения/записи HTTP; auth store от HTTP mode не отключается |
| C18 | identity/locks, store с AuthLockProviderInterface, cacheStore:null и оба null | Явный locks имеет прежний приоритет и сохраняется при сбросе только store; без него выбор store-provider/локального provider прежний; сброс обоих полей возвращает локальный путь |
| C19 | Конструктор/with/неверный старый вызов/оба вида сброса с инструментированными зависимостями | Ноль вызовов store/identity/locks при конфигурировании, включая clear/delete/deleteMultiple; исходные записи сохранены; зависимости не клонированы |
| C20 | Долгоживущий исходный клиент, копия с другим store/без store, успешное и ошибочное выполнение | Старый клиент не перенастроен; общий токен/identity не перемешиваются; нет скрытой очистки backend |
| C21 | clearCache/clearScope, атрибут Cache, runtime overrides, только store без P и только P без store | Store используется отдельно от параметров во всех путях; invalidation работает с прежними поколениями; null store не вызывает обращений к прежнему backend |
| C22 | Запись HTTP-ответа и токена из baseline старой версии при искусственных стабильных identity/времени | После переноса S/P ключи/формат пригодны без очистки и смены namespace; cache hit и reuse токена подтверждены независимо от нового алгоритма |

C13 сначала проверяет чистую пару GET в пустом backend, затем попадание в запись
исходного клиента. C22 использует сохранённые на baseline искусственные данные и
фиксированные часы/identity; не строить ожидаемые ключи новым кодом самой проверки.
Внешний Redis, сеть и реальные секреты для этих сценариев не нужны.

## Организация и доказательства

- Конфигурация — `tests/Unit/Core/ClientConfigTest.php` либо отдельный
  `ClientConfigCacheTest.php`; выполнение — существующие `tests/Unit/Cache/`,
  `tests/Unit/Auth/`, `tests/Unit/Resolver/` и интеграционные тесты по ответственности.
- Именованные fake clock/store/auth/transport размещать в tests/Support либо
  tests/Stubs. Проверять реальные ClientConfig/CacheConfig и HTTP/auth, не private
  helper или только свойства. Ожидания задаются по контракту, не по фактическому выводу.
- До изменения сохранить git HEAD/tree, PHP, SHA-256 исходников/оригинального probe,
  старые U01–U14 и материал для C22 в artifacts. Composer InstalledVersions не
  заменяет фактический commit: reference корневого checkout может быть устаревшим.
- После смены сигнатур оригинальный probe останется доказательством старого API.
  Подготовить отдельную адаптацию по миграции, не редактируя входящий issue.
  U06/U13/U14 проверяют исправление; для U07 показать осознанный перенос намерения,
  не обещать сохранить старый вызов cache:null. Для каждой адаптации указать различия.
- Исполняемые тесты и примеры переводятся на новый API в той же реализации. Не делать
  массовую замену слова cache: у других классов оно имеет самостоятельный смысл.

## Завершение

Все C01–C26 связаны с конкретными тестами в implementation.md. Адресные проверки,
`composer test`, PSR-12 и статический анализ затронутого кода, `composer check-docs`,
`composer analyse-docs`, оба архива `composer check-package`, `git diff --check`.

Миграция обязательна: публичные справочники, CHANEGLOG, API registry и клиентский
showcase обновлены одновременно. Старые объявления остаются только явно помеченными
примерами «до» и исходными доказательствами, а не работающими рекомендациями.
