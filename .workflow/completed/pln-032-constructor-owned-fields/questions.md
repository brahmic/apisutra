# Согласование AS-5

## D01. Граница первой версии

- **Статус:** отвечен, принят 2026-09-15.
- **Адресат:** владелец ApiSutra.
- **Закрывает:** окончательный contracts.md с приложением о массивах, приёмку
  D01–D36, принятие ADR-003 и готовность нового публичного режима к реализации.
- **Не зависит:** фиксация исходного дефекта, подготовка тестовой матрицы и план AS-6.

Принято явное правило `FieldRule::constructorValue(bool $allowMissing = false)`:
проверяем значение, созданное конструктором, не присваиваем повторно. Первая версия
покрывает scalar/null/конкретный enum, рекурсивные массивы этих значений и native
unions поддержанных типов. Произвольные объекты и собственные comparators не
добавляются. Missing разрешается отдельной опцией; required и запрет исходного null
сохраняют своё действие.

### Ответ автора issue и решение владельца

- **Источник уточнения:** сообщение автора issue о типах, переданное владельцем
  в текущем чате 2026-09-15. Исходные файлы issue не переписываются задним числом.
- **Источник решения:** после оценки реализуемости владелец ответил:
  «Отлично, фиксируй и доложи о готовности планов к реализации» (2026-09-15).
- **Область согласия:** контракт AS-5, включая рекурсивные массивы и технические
  границы сравнения. Ответ не выбирает оставшиеся варианты cacheConfig в плане 033.

Автор подтвердил, что для текущего блокера достаточно строкового признака, но
фиксированные списки и словари нужны общему контракту. Сравнивать следует результат
штатного преобразования входа со значением конструктора: скаляры строго, enum по
классу и case, null только с null; у списков учитывать длину/позиции, у словарей
ключи/значения без учёта порядка добавления. Правила рекурсивны. Проверка ограничена
конкретным свойством и не должна повторно писать readonly или валидировать весь DTO.

Решение реализуемо в общем пути гидратации без отдельной системы object equality.
Для типов после декодирования, числовых ключей, предела 512 контейнеров, ошибок
обеих сторон и стоимости зафиксировано [приложение](array-comparison.md).
Отдельных открытых вопросов автору issue или владельцу по 032 не осталось.

### Рассмотренные рекомендации

Первоначальный минимальный вариант scalar/null/enum закрывал воспроизведённый kind.
После вопроса владельца о стоимости рекомендация была расширена: массивы значений
требуют умеренной дополнительной работы — обхода, границ вложенности и тестов;
исключение массивов не было выводом об их высокой стоимости.

Промежуточное предложение сравнивать массив целиком через `===` **не принято**:
оно ошибочно учитывает порядок добавления ключей словаря. Его заменило принятое
рекурсивное сравнение по ключам с сохранением позиций элементов списка.

Объекты оставлены за границей осознанно: идентичность экземпляра, равенство состояния
и предметное равенство различаются. Автоматическое сравнение свойств, пользовательские
методы и новый comparator API требуют отдельного подтверждённого сценария.
Точные часы и численное обещание производительности не оценивались.

Контракт, приёмка и ADR-003 актуализированы по ответу; этап 1 завершён. Готовность
к коду не означает, что проверки D01–D36 уже прошли или возможность опубликована.
