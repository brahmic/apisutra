# Проверка полей DTO, инициализированных конструктором

- Дата создания: 2026-09-15
- Дата обновления: 2026-09-15

## Основание и результат

**AS-5 / F01, P1** из [входящего issue](../../issue/iss-003-apisutra-contracts/iss-003-readme.md).
[Требования AS-5](../../issue/iss-003-apisutra-contracts/upstream-requirements.md#as-5-построение-dto-со-свойствами-инициализированными-конструктором)
относятся к обычным моделям, которые конструктор дополняет постоянным признаком:
например, `public string $kind`, получающий `'known'` внутри конструктора.

Сейчас корректный `kind='known'` даёт `ConfigurationException` при повторной записи;
`kind='other'` даёт ту же ошибку, отсутствие kind — `required_field_missing`.
U15–U19 из [независимого probe](../../issue/iss-003-apisutra-contracts/artifacts/upstream-probe.php)
воспроизводят standalone, список и Returns после HTTP 200.

Цель: внешнее правило позволяет проверить значение источника относительно значения,
созданного конструктором, без повторной записи свойства. DTO сохраняет свой класс,
публичную форму и конструктор; наследование, интерфейс или атрибут ApiSutra не нужны.

## Архитектурное размещение

| Компонент | Изменение |
| --- | --- |
| [FieldRule](../../../src/Serialization/Rules/FieldRule.php) | Явный режим проверки поля и допуск Missing; неизменяемый descriptor |
| [RuleSetCompiler](../../../src/Serialization/Rules/RuleSetCompiler.php) | Проверка допустимости объявления без создания DTO и вызова его кода |
| [Hydrator](../../../src/Serialization/Hydrator.php) | Разделение аргументов конструктора, проверок его результата и обычных присваиваний |
| [HydratedProperty](../../../src/Serialization/Rules/HydratedProperty.php), [HydrationScope](../../../src/Serialization/Rules/HydrationScope.php) | Сохранение состояния и происхождения ожидаемого значения до проверки результата конструктора |
| [ScalarValues](../../../src/Serialization/Rules/ScalarValues.php) | Существующие правила типов и преобразований; без нового универсального валидатора |
| Внутреннее сравнение значений в Serialization/Rules | Область scalar/null/enum/array, ограниченная рекурсия и равенство; без mapper и публичного comparator |

Использовать общий `hydrateObject`/построение DTO. Специальные ветки в клиентах,
Returns, pagination или continuation не добавляются. Сериализатор продолжает
отправлять обычное свойство по существующим исходящим правилам.

Проверки, ожидающие конструктор, живут в локальном состоянии одного узла гидратации.
Не помещать ожидаемые/фактические значения или DTO в metadata cache/compiled rules.
Переиспользовать `HydratedProperty` и `SourceLocation`, сохраняя выбранный fallback,
Missing/Null/Present и Boundary после cast/provider.

## Граница

- Только явно отмеченные поля; поведение остальных DTO, включая ошибки прежнего
  fallback assignment, не меняется. Массовый пропуск `isInitialized()` запрещён.
- Первая версия: public stored property со scalar/enum/array-типом, при необходимости
  nullable или union из поддержанных типов. Рекурсивные массивы содержат только
  scalar/null/enum/array; произвольные объекты, ресурсы, property hooks и нетипизированные
  поля не поддерживаются. Сравнение не превращает строки элементов в числа само.
- Конструктор вызывается один раз при достижении фазы построения. Нельзя обходить его,
  пробно создавать DTO для introspection или переписывать readonly через обход PHP.
- Порядок defaults/casts и изоляция объектов после 031 сохраняются. Нового контейнера,
  factory registry, второго mapper, общего механизма бизнес-валидации нет.
- Специальные raw-типы, несколько extras receivers и перевод ошибок внешнего SDK
  остаются за пределами AS-5. Их наличие не блокирует этот план.
