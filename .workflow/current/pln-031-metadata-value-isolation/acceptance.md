# Приёмка изоляции значений metadata cache

- Дата создания: 2026-09-14
- Дата обновления: 2026-09-14

Контракт — [contracts.md](contracts.md). Матрица ниже задаёт обязательные проверки
реализации; сейчас ни одна строка не выполнена. Исходное состояние зафиксировано
в [baseline-state.json](artifacts/baseline-state.json): HEAD `eeb0b6a`, PHP 8.4.15,
433 теста / 1385 assertions, 33 наблюдения [metadata-probe](artifacts/metadata-probe.json).

После исправления ожидания исходного probe перестанут совпадать. Его результат
не переписывается: новый запуск сохраняется отдельным файлом с commit и командой.

## Матрица

Каждая строка, кроме структурной M15, проверяется при cache on и cache off; результаты
обоих режимов должны совпадать. M15 проверяется только при включённом кеше; при выключенном
для неё сравнивается лишь эквивалентность результатов. Независимость проверяется
идентичностью объектов и изменением состояния, а не только равенством массивов.

031 не меняет, в каких частях запроса применяется Cast: header, path и file его
по-прежнему не вызывают. Поддержка Cast в этих частях — отдельное изменение поведения.

| ID | Сценарий | Ожидаемый результат |
| --- | --- | --- |
| M01 | Constructor default `new Counter()`, два прямых `hydrate` | Разные объекты; изменение первого не видно во втором |
| M02 | То же через `DTO::from()` и клиент без environment override | Одинаковое поведение с прямым hydrate |
| M03 | Default `[new Counter()]` | Разные вложенные объекты |
| M04 | Значение для параметра пришло (включая null) | Счётчик конструктора default-объекта не растёт |
| M05 | Значение не пришло | Счётчик растёт ровно на 1 на каждый созданный DTO |
| M06 | `hydrateCollection` из трёх элементов без значения | Три независимых объекта, счётчик +3 |
| M07 | Выражение default бросает исключение | Исключение выходит так же, как исключение конструктора; DTO не создаётся |
| M08 | Scalar/enum/array defaults, required без default, variadic | Прежние значения и прежние ошибки |
| M09 | `DefaultValue(value: [new Counter()])`, Missing | Разные вложенные объекты в двух DTO |
| M10 | `#[Cast(CountingCast::class, new Seen())]`, hydrate дважды | Счётчики [1, 1] |
| M11 | Тот же Cast через DtoSerializer | [1, 1] |
| M12 | Тот же Cast в query и body через Serializer | [1, 1] для каждой части |
| M12a | Cast с объектным аргументом на header- и path-свойстве | Cast не вызывается, как до 031: header `"0"`, путь `/items/0` при обоих вызовах и режимах кеша |
| M13 | Вложенный wire DTO с этим Cast | [1, 1] |
| M14 | Cast с массивом объектов в аргументах | Независимые вложенные объекты |
| M15 | Cache on: атрибуты только со значениями, прогретый кеш | Экземпляр переиспользуется; число построений metadata и `newInstance()` не растёт с числом узлов (white-box проверка); критерии времени — раздел «Стоимость» |
| M16 | Returns → элементы пагинации и контейнер через withItems → итог CompositeFlow, один клиент | Независимые объекты на всех входах и между элементами страницы |
| M17 | Клиент из ClientRegistry, две операции, снятие внешних ссылок между ними | Изменение первой операции не видно во второй |
| M18 | Laravel `singletonIf`, долгоживущий контейнер, без сети | Как M17 |
| M19 | Два независимых клиента | Независимые кеши и объекты, как до исправления |
| M20 | Рекурсивный DTO, смена типов, прогрев metadata, ошибки cast | Прежние результаты; лишних вызовов DTO-конструктора нет |
| M21 | Кеш `RequestSpec` и `RequestDefaults` | Проверено отсутствие удержания объектов; при находке применено правило contracts.md |

## Стоимость

Метод выбран до изменения кода. [cost-benchmark.php](artifacts/cost-benchmark.php)
измеряет три преобразователя: Hydrator (одиночный DTO и коллекция из 100 элементов),
DtoSerializer и сборку частей запроса через Serializer. Каждый — для деклараций
только со значениями и с объектами, в трёх режимах: `warm` — один экземпляр
с прогретым кешем, `cold` — новый экземпляр и кеш на операцию, `off` — кеш выключен.
Каждый сценарий: разогрев, затем 7 прогонов фиксированного числа итераций; сохраняются
медиана, минимум, максимум, разброс и удержанная после прогона память.

Baseline дефектной версии — [cost-baseline.json](artifacts/cost-baseline.json):
`eeb0b6a`, PHP 8.4.15 CLI, OPcache CLI и JIT выключены, без Xdebug, WSL2.
Прогретый кеш на декларациях со значениями быстрее выключенного: Hydrator 17,6 мс
на 2000 операций против 4,0 мс на 300 (≈8,8 против 13,2 мкс), DtoSerializer
≈5,7 против 8,1 мкс, сборка частей запроса ≈12,5 против 18,3 мкс на операцию.

Абсолютные значения зависят от машины. При приёмке baseline-коммит и исправленная
версия измеряются подряд на одной машине с теми же настройками PHP; сохранённый
файл документирует метод и порядок величин.

| ID | Критерий | Условие приёмки |
| --- | --- | --- |
| P01 | Нет регрессии пути без объектов | Для `*.values.warm.*` медиана после исправления ≤ максимум baseline + разброс замера после исправления |
| P02 | Выгода кеша сохранена | Для каждого `*.values.*` и `*.objects.*` после исправления медиана на операцию в `warm` не выше `off` с учётом разброса обоих замеров |
| P03 | Нет удержания значений | При удвоении итераций удержанная память прогона не растёт пропорционально; M17 подтверждает отсутствие переноса состояния |
| P04 | Объектный путь | Время `*.objects.*` фиксируется для сравнения; дополнительные новые объекты — ожидаемая цена исправления, а не регрессия |

Процентные пороги и таймеры в обычных unit-тестах не вводятся. Измерения после
исправления сохраняются отдельным файлом с commit, настройками PHP и командой.

## Команды и завершение

```bash
vendor/bin/pest tests/Unit/Serialization --compact
php .workflow/current/pln-031-metadata-value-isolation/artifacts/cost-benchmark.php
composer test
composer lint
composer analyse
composer check-docs
```

Результаты, commit и новый вывод probe сохраняются в `artifacts/` этого плана.
План завершается после прохождения M01–M22 (включая M12a) и P01–P04, обновления документации из contracts.md
и записи в changelog. Затем 030 подключает исправленный гидратор к await.
