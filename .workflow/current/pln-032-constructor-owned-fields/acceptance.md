# Приёмка AS-5

Матрица проверяет [принятый контракт](contracts.md) и его
[правила массивов](array-comparison.md), решение
[D01 от 2026-09-15](questions.md#d01-граница-первой-версии). Отметок о прохождении нет:
реализация ещё не начата.
Каждой строке при реализации сопоставить тест/набор тестов в `implementation.md`.

## Граф, источник и совместимость

| ID | Сценарий | Ожидаемое поведение |
| --- | --- | --- |
| D15 | Переименование, dot-path, primary отсутствует/fallback найден; соседние данные и невыбранный alias | Проверенное поле потреблено, остальное в extras; sourcePath указывает фактический источник |
| D16 | Missing с цепочкой fallback, default и без default | Корректные Expected/sourceCandidates либо Boundary, без выдуманного входного значения |
| D17 | Одиночный nested, список/двумерный список, variants с known subtype, each | Один общий контракт, верные индексы и пути; конструктор каждого создаваемого узла не повторяется |
| D18 | Returns/unwrap с HTTP 200, успешный и конфликтующий ответ; result-first/dataOrFail/throwOnErrors/promise | Успех создаёт DTO; ошибка = hydration_error с HTTP-ответом/status и прежней цепочкой исключений |
| D19 | Тот же HTTP-ответ через response cache; pagination, CompositeFlow, Ready await и повторный awaitAs | Все используют гидратор клиента; одинаковые правила/ошибки без новых интеграционных обходов |
| D20 | Два независимых набора для одного класса, чередование success/mismatch/Missing на одном гидраторе; cold/warm/cache-off | Нет переноса flags/ожидаемых значений/результатов; без opt-in исходный U15 по-прежнему ConfigurationException |
| D21 | Прежние promoted/унаследованные и неинициализированные fallback свойства, nullable Missing, constructor defaults new | Прежнее поведение; обычные defaults/атрибуты сохраняют изоляцию 031, без лишних materializations |
| D22 | DTO-путь и sourcePath при unwrap + nested + mapping; пользовательский cast; секретное значение/ключ | Точный путь где известен, Boundary после cast; безопасный лог без значений и с маскированием неизвестных ключей |
| D23 | toArray и запрос с исходящим To и extras, вручную созданный объект | kind остаётся обычным исходящим свойством; receiver исключается только по прежнему контракту набора |

D19 использует существующие нейтральные фикстуры входов. Не требуется копировать
весь общий набор pagination/continuation тестов; нужны сквозные проверки именно
нового поведения и одного ошибочного Ready-ответа без изменения Pending/Ready.

D10 задаёт ожидаемые типы/значения вручную и дополнительно сравнивает обычное
поле с новым режимом: одна дифференциальная проверка без независимых ожиданий могла
бы скрыть одинаковую регрессию обоих путей. Исходные различия воспроизводит
[сохранённый probe](artifacts/legacy-typing-probe.php); результат и команды —
в [доказательствах готовности](artifacts/README.md).

## Рекурсивные массивы и границы сравнения

| ID | Сценарий | Ожидаемое поведение |
| --- | --- | --- |
| D24 | Пустой и непустой список scalar/null/enum; изменение длины, позиции, типа или enum case | Равенство только при совпадении позиций и значений; несовпадение = constructor_value_mismatch |
| D25 | Словарь и вложенные словари с перестановкой ключей; словарь внутри списка и список внутри словаря | Порядок ключей словаря не влияет; порядок значений по индексам списка влияет |
| D26 | Отсутствующий/добавленный ключ, null против отсутствия; числовые разреженные ключи, ключи 1 и '01' | Разный набор ключей не равен; null — присутствующее значение; никаких приведений ключей сравнением |
| D27 | Одинаковые связи 0 → a, 1 → b с разным порядком добавления; JSON-ключ '1'; декодированные пустые объект и список | Результаты точно по приложению: равенство по имеющимся PHP-ключам; различие array_is_list само по себе не даёт mismatch; утраченная JSON-форма не восстанавливается |
| D28 | Native array без shape с элементами '1'/1 и 10/10.0; array/nullable/union; list<int>/float, nullable/mixed/list, each, normalizeKeys и itemCast | Сравнение не приводит листья; заданные штатные преобразования выполняются один раз и сравнивается их итог; union не упрощается |
| D29 | Enum внутри массива: готовый case, строка после явного cast, разные enum-классы с одинаковым backing value; NAN | Совпадает только итоговый case; строка без преобразования не равна enum; NAN даёт mismatch |
| D30 | После преобразования вход содержит DTO/DateTime/stdClass/Closure/ресурс на любой глубине, также за первым различием длины/значения | invalid_field_type до конструктора; неподдерживаемое содержимое не маскируется mismatch; методы объектов не вызваны; явный cast может заранее дать допустимое значение |
| D31 | Те же неподдерживаемые значения установлены конструктором, включая Missing + allowMissing и раннее различие длины | ConfigurationException после одного вызова; весь результат отмеченного свойства проверен, вход не присвоен |
| D32 | 511/512/513 вложенных array-контейнеров, включая пустой последний; самостоятельный цикл и повтор конечного подмассива | До 512 включительно допустимо; превышение/цикл входа = hydration_depth_exceeded до конструктора; результата конструктора = ConfigurationException; повтор конечной ветви разрешён |
| D33 | Missing/default/provider для array: совпадение, конфликт, nullable null; allowMissing с неподдерживаемым результатом конструктора | Общая таблица состояний без исключений для array; provider/конструктор не повторяются, Boundary сохраняется |
| D34 | Массивное отмеченное поле под nested/list/unwrap + from/fallback, each/normalizeKeys/cast; секретный внутренний ключ | Mismatch и новые проверки области/глубины указывают на свойство целиком; верный SourceLocation либо Boundary; внутренние ключи/значения не раскрыты; ошибки shape сохраняют прежние пути |
| D35 | Широкий словарь, вложенные массивы, cold/warm/cache-off, два набора и неизменяемый вход; неотмеченное поле с объектом | Результат не зависит от порядка ключей/кеша; вход и значения не сортируются/не клонируются/не сериализуются; неотмеченное поле не сравнивается; пользовательские методы не вызваны |
| D36 | Returns с успешным словарём и переставленными ключами, затем mismatch; array через response cache и Ready await | Общий режим клиента: typed DTO либо hydration_error с HTTP-ответом; после Ready ошибка не превращается в Pending; array не получает отдельный путь построения |

D32 изолирует локальный предел сравнения: native array без рекурсивного shape,
подготовленный PHP-массив передаётся напрямую. Для shape действует и прежний предел
HydrationScope. D35 проверяет наблюдаемое поведение без порогов времени; отсутствие
сортировки/сериализации и линейный обход дополнительно проверяются при ревью кода.

## Организация проверок

- Новые нейтральные типы — отдельные файлы `tests/Stubs/`; тесты —
  `tests/Unit/Serialization/ConstructorOwnedFieldsTest.php` и дополнения существующих
  `ExternalHydrationEntriesTest`, `ExternalHydrationOriginTest`, `ExternalHydrationWireTest`
  по фактической ответственности. Имена новых файлов пока проектные.
- При объёме массивных datasets вынести их сценарии в отдельный тестовый файл
  того же модуля; проверять через публичную гидратацию, не private helper сравнения.
- Ожидания задаются по принятому контракту, а не вычисляются из результата.
  Успешные HTTP-сценарии проверяют тип DTO, данные и число запросов, не только status.
- Счётчик вызовов конструктора вынести в отдельный helper, чтобы он не стал новым
  гидрируемым public property фикстуры. Явно сбрасывать между сценариями.
- MockTransport с запретом посторонних запросов либо искусственный PSR-18 клиент;
  сеть, Laravel и API потребителя не нужны. Его полный граф принимается отдельно.
- До исправления сохранить исходные наблюдения и commit в `artifacts/`; после —
  отдельные новые результаты. U15–U19 исходного probe без opt-in обязаны сохранять
  старое поведение: target-проверки используют новый descriptor.
- После реализации 033 сохранить отдельную адаптацию ClientConfig-вызовов probe
  под cacheStore, без изменения проверок AS-5. Старое поведение U15–U19 означает
  исходы гидратации без opt-in, а не поддержку удалённых кеш-аргументов конструктора.

## Завершение

Адресные тесты → `composer test`; PSR-12 и статический анализ затронутого кода,
`composer check-docs`, `composer analyse-docs`, оба архива `composer check-package`,
`git diff --check`. Известные несвязанные baseline-ошибки фиксировать отдельно,
не выдавать их за проход проверки и не расширять план молча.

Публичный runnable-пример, реестр API, справочники и changelog входят в приёмку.
Результаты и commit записываются в плане перед переносом в `completed/`.
