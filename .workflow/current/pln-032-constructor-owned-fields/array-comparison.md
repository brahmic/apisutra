# Массивы в проверке значения конструктора

Принятая часть [контракта 032](contracts.md), решение
[D01 от 2026-09-15](questions.md#d01-граница-первой-версии).
Здесь зафиксированы правила массивов; порядок гидратации и подключения принадлежит
основному контракту. Это будущая возможность, не описание реализованного API.

## Область сравнения

Обе стороны — значение поля после штатной гидратации и значение, установленное
конструктором. Допустимы scalar, null, UnitEnum и рекурсивные PHP-массивы таких
значений. Проверка касается только явно отмеченного свойства и не записывает его.
Вложенные DTO, DateTime, stdClass, Closure, другие объекты и ресурсы не сравниваются.
Их свойства и методы не обходятся, JsonSerializable/toArray/Stringable не вызываются.

Native array не описывает тип элементов. Ни `constructorValue()`, ни PHPDoc
`list<int>` не превращают вложенную строку в число или строку в enum автоматически.
Если такое преобразование задано существующим shape/cast/provider, оно выполняется
обычным путём один раз. Проверяется его итог, с прежней политикой Strict/Legacy.
Raw stdClass может быть преобразован штатным явным cast в массив; ограничение
относится к полученному значению, а не к данным до этого преобразования.

## Ключи, списки и словари

У равных массивов совпадают число элементов, набор **существующих PHP-ключей** и
рекурсивно сравниваемые значения при каждом ключе. Null — существующее значение,
поэтому проверка наличия использует смысл array_key_exists, а не isset.
Порядок добавления ключей в PHP-массив не участвует в равенстве.

- Список имеет позиции 0..n−1; сравнение по соответствующим индексам сохраняет
  длину и порядок значений. Перестановка значений по индексам означает несовпадение.
- Словарь сравнивается по ключам и значениям; строковые и разреженные числовые
  ключи сохраняются. Для равенства не сортировать и не переиндексировать сами данные.
- Отдельного тега «список/словарь» после декодирования нет. Проверять оба массива
  независимым array_is_list и отклонять разницу нельзя: иной порядок добавления
  числовых ключей не должен делать равный словарь неравным. Массивы с одинаковым
  соответствием 0..n−1 → значение равны независимо от порядка добавления ключей.
  Если важна исходная форма списка, она проверяется прежним inputShape до сравнения.
- После assoc-декодирования `{}` и `[]` представлены одинаковым `[]`; новое правило
  их не различает. JSON-ключ `"1"` становится int 1, `"01"` остаётся string;
  сравнение использует тип ключа после декодирования и не восстанавливает JSON-текст.

Примеры ниже — PHP-значения **после** заданных преобразований:

| Левая сторона | Правая сторона | Результат |
| --- | --- | --- |
| `[1, 'x', null]` | `[1, 'x', null]` | Равны |
| `[1, 'x']` | `['x', 1]` | Не равны: значения на позициях различаются |
| `[1]` | `['1']` | Не равны: типы элементов различаются |
| `['a' => 1, 'b' => null]` | `['b' => null, 'a' => 1]` | Равны |
| `['a' => null]` | `[]` | Не равны: отсутствующий ключ не равен null |
| `[2 => 'x', 7 => 'y']` | `[7 => 'y', 2 => 'x']` | Равны |
| `[1 => 'b', 0 => 'a']` | `['a', 'b']` | Равны: индекс 0 содержит a, индекс 1 — b |
| `[1 => 'x']` | `['01' => 'x']` | Не равны: разные PHP-ключи |
| `['settings' => ['b' => 2, 'a' => 1]]` | `['settings' => ['a' => 1, 'b' => 2]]` | Равны на вложенном уровне |

В листьях действует строгое равенство скаляров/null и идентичность enum case из
основного контракта. Два enum-класса с одинаковым backing value не равны.
`NAN` даёт несовпадение и внутри массива. Ни общее PHP `==`, ни `===` для целого
массива, ни сравнение JSON/serialize не реализуют принятые правила.

## Допустимость, глубина и ошибки

Перед сравнением обе стороны должны быть проверены **целиком**. Раннее различие
длины, ключа или значения не маскирует неподдерживаемое содержимое той же стороны.
Преобразованный вход проверяется до конструктора; результат конструктора — после
его единственного вызова, даже если allowMissing разрешил отсутствие входа.

Глубина — число вложенных контейнеров array на пути от значения свойства, включая
пустой массив. Разрешено до **512 контейнеров включительно**, scalar/enum/null не
добавляют контейнер. Это локальный предел нового сравнения; существующий предел
HydrationScope на построение графа DTO не меняется и может сработать раньше.
Циклические массивы завершаются тем же ограничением глубины, отдельного публичного
reason для обнаружения ссылки нет. Повторное использование конечного массива в
нескольких ветвях разрешено и не считается циклом.

| Условие | Ошибка и момент |
| --- | --- |
| Преобразованный вход содержит объект, кроме enum, или ресурс | HydrationException, `invalid_field_type`, до конструктора |
| Преобразованный вход превысил предел, включая цикл | HydrationException, `hydration_depth_exceeded`, до конструктора |
| Конструктор создал неподдерживаемое/слишком глубокое/циклическое значение | ConfigurationException после одного вызова |
| Обе стороны допустимы, но различаются | HydrationException, `constructor_value_mismatch`, после одного вызова |

Для новых проверок путь указывает на свойство целиком, SourceLocation берётся из
основного контракта. Не выдавать внутренний индекс за точный sourcePath после
проекций или cast. Сообщение содержит причину, допустимый/фактический тип либо
предел; значения, ключи массива и сериализованное содержимое не включаются.
Прежние ошибки внутри shape/cast сохраняют собственный reason и путь.

## Размещение и стоимость

Достаточен внутренний компонент сравнения значений в Serialization/Rules.
Он отвечает за область значений и равенство; Hydrator — за фазы, инициализацию,
источник и доставку ошибок. Нового публичного comparator, registry или mapper нет.

Обход работает по ключам без сортировки, сериализации, клонирования и вызовов
пользовательского кода. Стоимость — O(N) посещённых элементов обеих сторон, память
обхода — O(D) по глубине; общие подмассивы считаются по каждому посещению.
Проверка выполняется только для отмеченных полей, значения не попадают в metadata.
Численного SLA по времени нет; приёмка проверяет ограниченную глубину, отсутствие
побочных эффектов и работу широких/вложенных массивов через публичную гидратацию.
