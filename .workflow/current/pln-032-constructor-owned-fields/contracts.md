# Контракт AS-5

Основание — [план 032](pln-032-readme.md). Статус: **принят 2026-09-15** по
[D01](questions.md#d01-граница-первой-версии). Это контракт будущего API, реализация
ещё не начата. Этот документ и его [приложение о массивах](array-comparison.md)
владеют поведением плана; ADR объясняет выбор, приёмка проверяет его.

## Подключение

Добавить неизменяемому `FieldRule` метод:

```php
public function constructorValue(bool $allowMissing = false): self;
```

Сигнатура зафиксирована. Метод объявляет независимый от
преобразования режим: **проверить значение, установленное конструктором, без записи**.
Повторное объявление этого режима — `ConfigurationException`, как у других
однократно задаваемых групп FieldRule. Входные атрибуты того же поля по-прежнему
конфликтуют с внешним правилом; нового приоритета над ними нет.

Пример будущей декларации для нейтральной модели из issue:

```php
use Brahmic\ApiSutra\Serialization\Rules\DtoRules;
use Brahmic\ApiSutra\Serialization\Rules\FieldRule;
use Brahmic\ApiSutra\Serialization\Rules\HydrationRules;
use Brahmic\ApiSutra\Serialization\Rules\RulePolicy;
use Brahmic\ApiSutra\Serialization\Rules\ScalarPolicy;

$rules = HydrationRules::create(new RulePolicy(scalars: ScalarPolicy::Strict))
    ->withDto(ConstructorOwned::class, DtoRules::create()
        ->field('kind', FieldRule::create()->constructorValue()->required())
        ->extras('extra'));
```

`ConstructorOwned` — класс из [фикстуры issue](../../issue/iss-003-apisutra-contracts/artifacts/fixtures/ConstructorOwned.php).
Новое правило применимо к readonly и обычному DTO. Оно не добавляет свойство,
не подменяет класс, не задаёт ожидаемую константу вместо конструктора.

## Допустимые объявления

Компилятор проверяет без пользовательского кода:

- Свойство существует, public, non-static, хранимое, без property hooks и default
  в самом объявлении. Последнее отличает результат конструктора от исходного default.
- У класса есть доступный effective constructor, в том числе унаследованный.
  Поле не является его параметром по имени, promoted или обычным: такие поля уже
  принадлежат пути аргументов конструктора и этой настройкой не переопределяются.
- Native-тип: `int`, `float`, `string`, `bool`, literal `true`/`false`/`null`,
  конкретный enum, `array` либо nullable/union из этих типов. `mixed`, `object`,
  произвольный класс, интерфейс, intersection и нетипизированное поле отклоняются.
  Содержимое array проверяется во время гидратации: только рекурсивные массивы,
  скаляры, enum и null. PHPDoc сам по себе не задаёт преобразование элементов.
- Поле не является extras receiver. Действующие конфликты с профилями и входными
  атрибутами сохраняются. Исходящий `To` сам по себе не конфликтует.
- Допустимы mapping/fallback, required, forbidExplicitNull, default, policy,
  cast и noTransform. Из ValueShape разрешены scalar, mixed, nullable и list,
  рекурсивно составленные из этих форм; mixed не снимает проверку допустимых значений.
  DTO/variants в любом узле result-shape отклоняются при компиляции: произвольные
  объекты не входят в область сравнения. Результаты пользовательских обработчиков
  проверяются после штатных преобразований, без их вызова при компиляции.

Нельзя узнать reflection-ом, исполнит ли тело конструктора присваивание.
Поэтому отсутствие инициализации проверяется после единственного вызова конструктора
и означает `ConfigurationException`: модель не выполнила объявленный договор.

## Порядок выполнения

1. Обычным путём прочитать primary/fallback и сохранить реальное состояние источника.
2. Проверить `required()` и `forbidExplicitNull()` до преобразований/defaults.
3. Применить inputShape, нормализацию пустой строки, default/provider, shape/cast
   и проверку native-типа в существующем порядке. Проверить допустимость полученного
   значения целиком, включая содержимое массива и предел вложенности; не вызывать
   преобразования второй раз. Missing не является значением для этой проверки.
4. Подготовить аргументы конструктора и обычные fallback assignments. Помеченное
   поле исключить из списка присваиваний; ожидаемое значение/состояние и SourceLocation
   сохранить в локальном списке проверок текущего узла.
5. Если ожидаемое значение осталось Missing и `allowMissing=false`, выдать
   `required_field_missing` до вызова конструктора. При `allowMissing=true`
   перейти к построению без сравнения этого поля с отсутствующим входом.
6. Вызвать конструктор один раз. Сразу после него проверить инициализацию всех
   отмеченных свойств, допустимость их значений и совпадение с разрешёнными
   значениями, в порядке metadata. При allowMissing тоже проверить инициализацию
   и допустимость результата конструктора. Проверка выполняется до обычных
   fallback assignments; другие свойства повторно не валидируются.
7. Если проверки успешны, выполнить обычные присваивания оставшихся свойств.

Существующие два способа вызова конструктора в Hydrator сохраняют свои гарантии.
Низкоуровневое выделение объекта в текущем fallback-пути не означает разрешения
пропустить constructor invocation. Не создавать пробный экземпляр и не вызывать
конструктор повторно после обнаруженного конфликта.

Все обычные проверки входа выполняются до конструктора. Если ошибка обнаруживается
только сравнением с его результатом, конструктор уже выполнился; отката его побочных
эффектов нет. Исключение самого конструктора сохраняет существующую доставку и не
превращается в ошибку несовпадения поля.

## Состояния

`allowMissing` относится к **неразрешённому** значению после defaults, не разрешает
исходный null и не отменяет `required()`.

| Вход и правило | Результат |
| --- | --- |
| Present, после преобразования совпадает | DTO; записи в отмеченное свойство нет |
| Present, тип неверен | Существующий `invalid_field_type`/другой профильный reason до конструктора |
| Present, тип корректен, значение отличается | `constructor_value_mismatch` после конструктора |
| Missing, `required()` | `required_field_missing` до defaults и конструктора |
| Missing, без required, default дал значение | Сравнить default с результатом конструктора |
| Missing, default отсутствует, allowMissing=false | `required_field_missing` до конструктора |
| Missing, default отсутствует, allowMissing=true | Сохранить значение конструктора; проверить инициализацию и допустимость значения |
| Missing, allowMissing=true и required | Required побеждает; Missing остаётся ошибкой |
| Null и forbidExplicitNull | `explicit_null_not_allowed` до defaults и конструктора |
| Null без запрета, несовместим с native-типом | `null_not_allowed` |
| Допустимый Null | Сравнить с null; конструктор с ненулевым значением даст mismatch |
| Default/provider для Null вернул значение | Обычные преобразования и сравнение, без отмены раннего forbidExplicitNull |
| Конструктор не заполнил поле, даже при allowMissing | `ConfigurationException`, без присваивания вместо конструктора |
| Преобразованный вход содержит неподдерживаемое значение или слишком глубокий массив | Ошибка гидратации до конструктора по приложению о массивах |
| Конструктор создал неподдерживаемое значение или слишком глубокий массив | `ConfigurationException` после одного вызова, в том числе при allowMissing |

## Равенство и преобразования

Сравниваются **типизированные значения**. Эталон — итоговое значение обычного
записываемого поля того же Hydrator, с тем же native-типом, политикой и набором
преобразований, но без constructorValue. Не сравнивать исходную JSON-строку с enum
и не добавлять приведение ради успешного совпадения. Отдельный setValue не является
эталоном всего пути гидратации.

- Scalar/null: `===`. Для `float` после штатного расширения целого сравнивается
  float; `10` при допустимом int → float совпадает с `10.0`. В union `int|float`
  сохраняется реально выбранный тип, `10` и `10.0` различаются при строгом сравнении.
- Enum: один и тот же case (`===`), включая unit enum, переданный готовым значением.
- Strict сохраняет запрет строки/boolean вместо чисел, переполнение int и границу
  точного int → float. Legacy сохраняет существующие scalar conversions.
- В Legacy сохраняется весь путь обычного поля, включая результат штатного caster
  и допустимую финальную типизацию при записи. Например, обычный float|string ← 5
  даёт string "5", bool|int ← 'false' — false. Отдельный setValue дал бы 5.0 и true.
  Но с noTransform обычный Hydrator тоже даёт 5.0 и true: подменять его результат
  безусловным ScalarValues::coerce нельзя. Та же граница важна после пользовательского cast.
- Проверить это дифференциально для обычного поля и нового режима. Переиспользовать
  подходящие scalar helpers, а недостающую финальную типизацию выполнить без пробного
  DTO/записи или повторного вызова обработчиков. Не выбирать первый член union:
  ReflectionUnionType даёт канонический порядок, не порядок текста объявления;
  поведение определяется эталонным путём Hydrator. Перестановка типов в записи
  эквивалентного union не должна менять результат нового режима.
- `NAN` не равен самому себе; произвольная float-tolerance не вводится.
- Массивы: рекурсивное сравнение значений по ключам. Для списков важны позиции
  элементов, для словарей порядок добавления ключей несущественен. Точные правила
  ключей, предела вложенности, ошибок и стоимости — в [приложении](array-comparison.md).
  Сравнение не добавляет преобразований элементов массива.
- DateTime, DTO и другие произвольные объекты, ресурсы и пользовательские comparators
  не поддерживаются, в том числе внутри массивов. Enum — явное исключение.

## Extras и происхождение ошибки

Проверяемое поле учитывается как прочитанное, даже при отсутствии физической записи.
Выбранный primary/fallback потребляется; невыбранный alias и соседи dot-path остаются
в extras. Отсутствующий ключ не добавляется в источник и ничего не потребляет.

Для нового mismatch использовать `HydrationException::invalidValue()` с reason
`constructor_value_mismatch`, DTO-путём и **типами** expected/actual. Значения
ожидаемого и фактического признака не включать в message/context/logContext.
Одинаковые типы при mismatch допустимы: различие объясняет reason.

Ошибка после конструктора проходит через сохранённый SourceLocation конкретного
поля, а не заново вычисленное имя. Это сохраняет nested/list/unwrap и выбранный alias:
например, path `data.items[0].kind`, sourcePath `/data/items/0/meta/type`.
После произвольного cast/provider остаётся Boundary, как в действующем контракте;
не обещать восстановить точный внутренний путь пользовательского преобразования.
Новые проверки сравнения/допустимости массива указывают на проверяемое свойство
целиком. Его внутренние ключи и значения не выводятся; индекс первого различия
и обратное отображение each/normalizeKeys не входят в новый контракт. Ошибки самих
штатных преобразований сохраняют прежние более подробные пути.

ConfigurationException остаётся для неверного объявления и неинициализированного
или неподдерживаемого значения конструктора. Ошибка данных при HTTP сохраняет ProviderResponse/status,
попадает в `hydration_error` и штатные режимы результата/исключений.

## Совместимость и cache

Без нового режима `isInitialized()` сохраняет текущий смысл. Promoted parameters,
ещё не заполненные свойства, наследование, порядок обычных преобразований и область
наборов разных клиентов не меняются.

В кеше остаются descriptors/reflection. Проверки и ожидаемые значения — на узел;
конструктор, default и cast не вызываются при компиляции или прогреве. Критерии
изоляции объектов из [031](../../completed/pln-031-metadata-value-isolation/contracts.md)
сохраняются. Serializer может читать новый descriptor при проверке набора, но
не выполняет constructorValue и не исключает такое свойство из запроса.
