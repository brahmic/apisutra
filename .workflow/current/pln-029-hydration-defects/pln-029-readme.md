# Исправления текущей гидратации и её документированного контракта

- Дата создания: 2026-09-14
- Дата обновления: 2026-09-14
- Статус: новый

## Основание и границы

[Рецензия aud-006](../../audit/aud-006-declarative-dto/peer-review.md) и
[35 воспроизведений](../../audit/aud-006-declarative-dto/artifacts/peer-review-results.json)
подтвердили F8 — сломанный документированный одиночный Nested, F5 — неполный DTO path
ошибки provider, F7 — неработающие для гидратации источники registry вопреки описанию.
F6 требует закрепить Present-provider + Nested регрессиями и руководством.

План отделён от [pln-028](../pln-028-declarative-dto/pln-028-readme.md).
Исправления не требуют внешнего реестра правил, extras-receiver, sourcePath,
новой scalar-политики или PHPDoc parser. Новые механизмы pln-028 должны использовать
исправленную основу. Настоящий документ не запускает реализацию.

## Готовность и границы совместимости

Воспроизведения дефектов и контрольное состояние готовы; можно начинать реализацию
с регрессионных тестов. При уточнении влияния изменений 2026-09-14 выбран узкий
объём F7: исправить документацию и проверки источников, сохранив фактическое
поведение гидратации. Constructor/client/global/extension registry не получают
нового влияния на DTO. Публичный аргумент Hydrator сохраняется без runtime-warning
и без удаления; профильные и property casts работают как прежде.

Ожидаемые изменения выполнения:

- корректный одиночный объект из JSON с Nested начинает успешно гидратироваться;
- некорректный одиночный объект получает структурированную ошибку вместо TypeError
  или ошибки по фиктивному индексу списка;
- path ошибки provider дополняется пропущенным сегментом поля. Проверки/обработчики,
  сопоставляющие прежние неточные пути, потребуют обновления.

Форматы успешных запросов/ответов вне исправленного одиночного Nested, scalar
conversions, missing/null/defaults, списки и typed collections должны сохраниться.
Отдельно проверить неоднозначные Nested-декларации, union-типы и пользовательские
коллекции: их совместимость нельзя гарантировать до выбора правил и тестов.
Закрепление Present-provider ограничено тестами и описанием существующего поведения.

| Приоритет | Находка | Результат |
| --- | --- | --- |
| P1 | F8 | JSON-объект создаёт одиночный Nested DTO; DTO не конструируется как коллекция. |
| P2 | F5 | HydrationException provider получает сегмент поля и весь путь родителей/unwrap. |
| P2 | F7 | Документация и тесты различают constructor/client/global/extension registry, профиль и property Cast. |
| P2 | F6 | Present-provider и совместные Null/Present проверки закреплены тестом и руководством. |

## Работы

### 1. Одиночный Nested

- [ ] Перенести C01–C08 в основные тесты с именованными фикстурами. Проверить пример
  docs/guides/dto.md с public-свойством, constructor promotion, plain readonly-child,
  DtoInterface-child и подготовленный PHP-объект.
- [ ] Выбирать одиночную гидратацию и коллекцию по объявленному назначению свойства
  и атрибутам, а не по одному is_array. Зафиксировать правила для Nested.type,
  native-типа, nullable/union, From/Nested.from и fallback. Неоднозначную конфигурацию
  отклонять с ConfigurationException, а не случайным вызовом конструктора.
- [ ] Для одиночного объекта вызывать существующий constructor-first Hydrator ровно
  один раз, с теми же проверками обязательности и типов. Не вызывать
  wrapCollection/new DTO($items) для одиночного свойства.
- [ ] Проверить valid/missing/null/scalar/array/object, вложенную ошибку поля и
  объект с единственным полем-массивом. Неправильные данные дают HydrationException
  с reason и DTO path; голый TypeError и безымянная оболочка в pipeline недопустимы.
- [ ] Сохранить списки, typed collections, each, itemCast, discriminator Value/Key,
  unknown policies и прежний приоритет Nested над property Cast.
- [ ] Проверить standalone и Returns после настоящего JSON decode, сохранённый
  HTTP-ответ и отсутствие retry при hydration error. Уточнить пример и кардинальность
  Nested; не обещать восстановить утраченное различие JSON `{}`/`[]`.

### 2. Путь ошибки provider

- [ ] Проверить HydrationException provider при Missing, Null и Present на корне,
  внутри одиночного DTO, элемента списка и после unwrap.
- [ ] Добавлять сегмент поля вокруг вызова provider так же, как вокруг casts/Nested.
  Сохранить reason, expected/actual, previous и уже имеющийся суффикс пути;
  не терять и не удваивать префиксы.
- [ ] Не менять порядок нормализации/defaults, Keep, пропуск нормализации при Cast
  и autodefault typed collections. ConfigurationException не превращать в ошибку данных.
- [ ] Для C15/C16 ожидать guardedChild.count/data.guardedChild.count.
  Field metadata нового реестра и sourcePath для исправления не нужны.

### 3. Реестры casts и документация

- [ ] Разделить тесты constructor registry, ClientConfig.casts, global registry,
  extension registry, hydration profile и property Cast. Plain-фикстура не должна
  содержать профиль, маскирующий неработающий источник.
- [ ] Уточнить casts.md, комментарий Hydrator::default(), описание CastRegistry::global()
  и примеры: на исходном состоянии первые четыре источника не участвуют в гидратации,
  профильный registry участвует. Отдельно проверить сериализацию запросов.
- [ ] Сохранить публичный аргумент Hydrator::$casts и явно описать отсутствие его
  участия в гидратации. В рамках 029 не активировать constructor/client/global/extension
  registry и не добавлять runtime-депрекации. Подключение новых правил относится
  к явному изолированному API pln-028. Выполнение pln-028 не является условием
  исправления ложного описания существующих реестров.

### 4. Контракт Present-provider

- [ ] Добавить основной тест провайдера для Present: значение проверяется и
  возвращается перед Nested; valid/invalid shape и known/unknown discriminator.
- [ ] Проверить один provider с Null/Present для nullable-list: missing → default,
  null → ошибка, list → принят, associative/sparse → ошибка; неверный элемент
  сохраняет индекс. DefaultValue не делать повторяемым без потребности.
- [ ] Описать вычисление и отказ от значения, состояние при Keep/non-Keep/
  EmptyStringAsNull/Cast, путь ошибки. Это закрепление ранее воспроизведённой
  комбинации; не выдавать её за уже рекомендованный рецепт документации релиза.

## Приёмка

Начать с затронутых Serialization/ResponseHydrator тестов, затем выполнить
`composer test`, `composer lint`, `composer analyse`, `composer check-docs`.
Проверить без Laravel и сети, с синтетическими данными и контролем количества
конструкторов/HTTP-вызовов. Исходные probes aud-006 сохраняют старые наблюдения:
после исправления F8/F5 часть ожиданий должна перестать совпадать. Новые результаты
сохранить отдельно в artifacts этого плана с commit, командами и логами.

- [ ] Одиночный Nested проходит standalone/JSON/Returns; плохие данные дают
  структурированную ошибку с корректным путём.
- [ ] F5 исправлен на всех уровнях, работающие defaults/providers/списки сохранены.
- [ ] F7 не маскируется профилем в тесте; описание каждого источника соответствует
  принятому и проверенному поведению.
- [ ] Present и совместный Null/Present provider закреплены тестом и руководством.
- [ ] Проверки пройдены, evidence сохранено, pln-028 использует исправленный контракт.
- [ ] Статус и каталог изменены на завершён/completed только после приёмки.
