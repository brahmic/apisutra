# Разделение хранилища и параметров кеша клиента

- Дата создания: 2026-09-15
- Дата обновления: 2026-09-15
- Статус: принято

## Контекст

[AS-6](../issue/iss-003-apisutra-contracts/upstream-requirements.md#as-6-корректное-копирование-и-переопределение-конфигурации-кеша)
выявил потерю store при копировании и игнорирование нового cacheConfig.
ClientConfig допускает store или цельный CacheConfig через cache, а также отдельный
cacheConfig со своим store. Несколько источников требуют приоритетов и особой
null-семантики; HTTP и auth читают их в разном порядке.

Владелец предложил устранить неоднозначность архитектурно и 2026-09-15 допустил
миграцию ради более чистого и гибкого API. Ответ и пересмотр прежних K01/K02
зафиксированы в [K03](../current/pln-033-cache-config-copy/questions.md#k03-разделение-api-и-миграция).

## Решение

В том же [плане 033](../current/pln-033-cache-config-copy/pln-033-readme.md) заменить
cache на cacheStore, принимающий только PSR-16 store или null; удалить store из
CacheConfig. Блок настроек сохраняется как независимый аргумент cacheConfig.
Совместимые алиасы старых форм не оставлять: они вернули бы второй путь объявления.

Конкретные сигнатуры, defaults, with/null, ошибки и границы HTTP/auth принадлежат
[контракту](../current/pln-033-cache-config-copy/contracts.md), действия потребителя —
[миграции](../current/pln-033-cache-config-copy/migration.md). Этот ADR объясняет выбор,
но не дублирует таблицы поведения. Новый API ещё не реализован.

## Последствия

- Store и параметры меняются независимо; специальное слияние двух источников
  исчезает, копирование сводится к обычному сохранению/замене полей.
- HTTP/auth читают один источник; CacheConfig и разрешение request-параметров
  больше не переносят store. Ссылка в CacheExecutionState остаётся состоянием вызова.
- Клиент может менять TTL/mode/identity/locks без переподключения store и менять
  store без восстановления блока параметров. Общие зависимости не клонируются.
- Раздельные хранилища HTTP и auth не добавляются. identity/locks остаются в текущем
  блоке с прежним назначением; metadata cache и rate-limit backend не затрагиваются.
- Это несовместимая смена аргументов/полей. Обновление включает потребителей ядра,
  SDK-фабрики в примерах, тестовые helpers, документацию, API registry и миграцию.
- Прежние правила совместимости N2 и конфликтов двух store заменены новым контрактом.
  Намерения сохраняются: отсутствие скрытого выбора, независимая замена параметров,
  отсутствие очистки backend. Имена и категории ошибок старых вызовов не сохраняются.

## Рассмотренные альтернативы

| Вариант | Причина не выбирать |
| --- | --- |
| Согласовывать старую пару в одном helper | Исправляет баги, но сохраняет избыточность публичного API и зависимость null от формы ввода |
| Переименовать cache, оставив CacheConfig.store | Два источника store остаются |
| Единственный цельный CacheConfig со store | Требует отдельного контракта изменения только параметров; хуже отражает выбранную независимость store и настроек |
| Поддерживать старые и новые аргументы одновременно | Возвращает приоритеты и конфликты, которые решено убрать |
| Заодно разнести HTTP/auth на разные конфигурации | Самостоятельный объём с новыми правилами identity/locks; для AS-6 не требуется |

Предшествующее обсуждение и его пересмотр сохранены в
[архитектурном разборе](../current/pln-033-cache-config-copy/architecture-review.md).
