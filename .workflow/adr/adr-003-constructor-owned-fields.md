# Явная проверка значений, созданных конструктором DTO

- Дата создания: 2026-09-15
- Дата обновления: 2026-09-15
- Статус: принято

## Контекст

[AS-5](../issue/iss-003-apisutra-contracts/upstream-requirements.md#as-5-построение-dto-со-свойствами-инициализированными-конструктором)
требует сохранить независимую модель, конструктор которой назначает признак
варианта. Нынешний fallback assignment пытается записать его повторно и отклоняет
даже корректные данные. Простой пропуск уже заполненных свойств скрыл бы конфликт.

Публичная граница существующих [внешних правил](adr-002-external-hydration-rules.md)
позволяет описать входное поведение без атрибутов/наследования на модели.

## Решение

Расширить FieldRule явным режимом проверки результата конструктора. Конкретная
сигнатура, ограничения типов, Missing, порядок нормализации и сравнения, ошибки
и совместимость принадлежат [контракту 032](../completed/pln-032-constructor-owned-fields/contracts.md).
Поведение не активируется автоматически для всех уже инициализированных свойств.

Runtime-состояние проверки живёт в Hydrator на одном узле. Компилятор хранит только
описание правила и проверяет декларацию без пользовательского кода. Источник поля
сохраняется существующими HydratedProperty/SourceLocation/SourceConsumption.

Решение принято владельцем 2026-09-15 по
[D01](../completed/pln-032-constructor-owned-fields/questions.md#d01-граница-первой-версии).
Поддержаны скаляры, null, enum и рекурсивные массивы этих значений. Списки сохраняют
позиции элементов; словари не зависят от порядка добавления ключей. Технические
границы PHP-представления и ошибок принадлежат
[приложению контракта](../completed/pln-032-constructor-owned-fields/array-comparison.md).
Реализация пока не начата; принятие ADR не объявляет API уже доступным.

## Последствия

- Для настроенного поля конструктор сохраняет ответственность за значение;
  неверный ответ даёт ошибку гидратации с источником вместо повторной записи.
- SDK может использовать собственные DTO через один общий гидратор и все его входы.
- Появляется публичная декларация. Её надо проверить в реестре API, документировать
  и сопровождать регрессионными тестами вместе с изоляцией metadata cache.
- Проверка несовпадения выполняется после конструктора; уже выполненные им эффекты
  не откатываются. Поэтому контракт явно различает ошибки до и после построения.
- Общая библиотека сравнения объектных графов и фабрика построения DTO не появляются.
- У нового режима есть ограниченный обход массивов после преобразований; он не
  вызывает пользовательские методы равенства и не меняет значения ради совпадения.

## Альтернативы

| Вариант | Причина не выбирать в этом объёме |
| --- | --- |
| Всегда пропускать initialized property | Не проверяет заявленное значение источника |
| Всегда сравнивать все initialized properties | Меняет поведение существующих DTO без включения нового правила |
| Не вызывать конструктор | Теряет инварианты модели и противоречит AS-5 |
| Добавить DTO factory registry | Слишком широкая граница; возвращает интегратору mapping, диагностику и extras |
| Вручную собирать каждый DTO в cast | Локальный обход, но не общий декларативный контракт всех входов |
| Добавить атрибут/интерфейс к модели | Не решает исходное требование независимых моделей |
| Сравнивать массив целиком через === | Ошибочно учитывает порядок добавления ключей словаря |
| Использовать общее PHP == | Ослабляет типы листьев и сравнивает неподдержанные объекты |
