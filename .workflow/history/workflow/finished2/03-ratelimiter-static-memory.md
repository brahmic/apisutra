# План 03: отказ от static памяти в RateLimiter (P0)

## Проблема
`src/RateLimiter.php` использует `static array $memory`, из‑за чего лимиты могут «перетекать» между клиентами в одном процессе и между тестами. Это ломает изоляцию.

## Рекомендованное решение
1) Убрать `static` и хранить состояние лимитов на уровне экземпляра `RateLimiter` (per‑client).
2) Ключ по умолчанию оставить **на уровне baseUrl**, чтобы лимит был общим и не размазывался по параметрам.
3) Добавить возможность переопределить ключ rate limit с явным приоритетом: runtime‑override (RequestOptions) → атрибут → дефолт baseUrl.

## План работ
1) В `RateLimiter` заменить `static $memory` на обычное свойство экземпляра.
2) В `RateLimitApplier` сохранить дефолтный ключ как `hash(baseUrl)`.
3) Добавить `key` в `RateLimitConfig` и `#[RateLimit]` (опционально) + поддержку override через `RequestOptions`, приоритет: override → атрибут → дефолт.
4) Добавить тесты:
   - изоляция per‑client (два клиента не делят лимит);
   - дефолтный ключ по baseUrl;
   - кастомный ключ (если задан) меняет bucket.
5) Прогнать тесты и убедиться, что поведение без кастомного ключа не изменилось.

## Нюансы
- Хешировать параметры запроса по умолчанию **не нужно** — это ослабит лимит.
- Без `cache` лимиты остаются per‑client (в памяти процесса).
