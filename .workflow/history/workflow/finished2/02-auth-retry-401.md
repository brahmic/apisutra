# План 02: корректный auth‑retry при 401 (P0)

## Проблема
Текущая логика 401 смешивает два контура:
1) общий retry (для 5xx/429/исключений);
2) auth‑refresh (при 401).

Исторически был одноразовый флаг, который разрешал только один refresh на запрос. Это не соответствовало `authRetryAttempts`.

## Комплексный анализ (бизнес‑логика)
Инварианты пакета:
- 401 при `authRetryOn401=true` должен инициировать refresh до лимита.
- Общий retry **не применяется к 401**, если включён `authRetryOn401`.
- `shouldRefresh()` используется **до запроса**, но 401 — отдельный сценарий.
- `NoAuth`/`withoutAuth()` полностью отключают аутентификацию.

Риски текущей реализации:
- При `forceRefresh` ожидание лока всё равно опирается на `shouldRefresh()`, из‑за чего refresh может быть пропущен даже при 401.
- `authRetryAttempts` может трактоваться дважды: лимит 401‑циклов и лимит внутренних попыток refresh.

## Рекомендованное решение
1) **Единая семантика `authRetryAttempts`**: это лимит **числа refresh‑циклов при 401**.
2) **Force‑refresh при 401 действительно принудительный**: lock‑ожидание не должно отменять refresh по `shouldRefresh()`.
3) **401 исключён из общего retry** при включенном `authRetryOn401`.
4) Если нужен отдельный лимит на retry самого refresh‑запроса — ввести **новый параметр** (например, `authRefreshAttempts`), иначе refresh делается один раз.

## План реализации
1) `RetrySender`:
   - заменить одноразовый флаг на счётчик `authRetryUsed`;
   - сравнение с `authRetryAttempts`;
   - при 401 и `authRetryOn401=true` запускать refresh до лимита и **не** включать общий retry.
2) `AuthHandler`:
   - добавить `forceRefresh` для 401;
   - при `forceRefresh` не выходить из ожидания лока по `shouldRefresh()`;
   - если применяется единственный лимит — убрать внутренний цикл retry refresh (или параметризовать отдельным лимитом).
3) Тесты:
   - несколько последовательных 401 до `authRetryAttempts`;
   - `authRetryAttempts=0` → refresh не выполняется;
   - `forceRefresh` не отменяется логикой лока.
4) Обновить `workflow/tests/10-auth.md` — зафиксировать инвариант.

## Финальные ожидания
- 401 → refresh (до `authRetryAttempts`) → повтор запроса.
- Общий retry **не применяется** к 401 при включенном `authRetryOn401`.
- `authRetryAttempts=0` → никакого refresh при 401.
- Лок не может отменить принудительный refresh.
- Семантика `authRetryAttempts` однозначна и документирована.
