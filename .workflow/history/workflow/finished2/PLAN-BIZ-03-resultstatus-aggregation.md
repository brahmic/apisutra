# План: агрегация ResultStatus при наличии PARTIAL

## Цель
Зафиксировать правила вычисления итогового `ResultStatus` для batch/pool при наличии частичных результатов (`PARTIAL`).

## Контекст
Сейчас в `ResultCollection::summarize()`:
- `PARTIAL` учитывается как «ни успех, ни ошибка».
- Если все результаты PARTIAL → итоговый статус становится `SUCCESS`.

Это может конфликтовать с определением:
`PARTIAL — частичный успех, есть данные и ошибки`.

## Вопрос для согласования
Как трактовать `PARTIAL` в агрегировании:
1) **Считать как и успех, и ошибку** (любой PARTIAL делает итог PARTIAL).
2) **Считать как ошибку** (PARTIAL считается failed при агрегации).
3) **Отдельная категория** (ввести `partialCount` в сводке и отдельные правила).

## Рекомендация
Вариант 1: PARTIAL → итоговый статус `PARTIAL`, если есть хотя бы один PARTIAL.
Это соответствует смыслу «есть данные и ошибки».

## Шаги
1) Утвердить правило агрегации.
2) Обновить `ResultCollection::summarize()` с учётом PARTIAL.
3) При необходимости расширить `ResultSummary` (например, `partial` count).
4) Обновить документацию по статусам в `batch`/`pool` при необходимости.

## Критерии приёмки
- Итоговый статус соответствует согласованным правилам.
- Документация и код не расходятся.

## Риски
- Изменение влияет на статус batch/pool результатов в случаях частичных данных.
