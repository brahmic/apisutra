# План: исключить двойной retry при 401

## Цель
После refresh‑аутентификации не применять общий retry для того же ответа 401.

## Контекст
Файл: `packages/brahmic/apisutra/src/Pipeline/Transport/RetrySender.php`

## Проблема
При 401 выполняется refresh и `continue`, затем общая логика `shouldRetry()` может снова вернуть `true` для 401.

## Шаги
1) Добавить флаг `handledAuthRetry` в `sendWithRetry()` и сбрасывать его на новый запрос.
2) Если 401 обработан через auth‑retry — пропускать `shouldRetry()` для текущего ответа.
3) Сохранить логику повторной отправки через `RetryHandler`.

## Критерии приёмки
- 401 обрабатывается либо auth‑retry, либо общим retry, но не обоими.
- Логирование сохраняется (warning при auth‑retry).

## Риски
- Скрытый повтор может исчезнуть.  
  Решение: добавить тест‑кейс на 401 + retryOn.
