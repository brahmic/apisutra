# Временные файлы для архивов

## Цель
Стабильная работа `ArchiveResponse` с ZIP/TAR через временные файлы внутри пакета `apisutra` с гарантированной очисткой при ошибках.

## Область и ограничения
- Реализация находится внутри `packages/brahmic/apisutra`.
- Внешний пакет `spatie/temporary-directory` поддерживается **опционально** и не является обязательной зависимостью.
- Temp‑файлы создаются только для работы `ArchiveResponse` и связанных обработчиков ответов.
- Контент архива уже находится в памяти; temp‑файл нужен исключительно для API `ZipArchive`/`PharData`.

## Ключевые требования
- Временные файлы **допустимы** и используются по умолчанию.
- **Очистка обязательна** при любой ошибке в ходе работы с архивом.
- Должна быть возможность указать кастомный temp‑dir (контейнеры, read‑only FS, безопасность).
- Выбор реализации делается **через конфиг или DI**, без скрытой магии.
- ZIP требует `ext-zip`, TAR/TAR.GZ требует `ext-phar`.
- Для `tar.gz` обязательно использовать корректный суффикс файла.

## Конфигурация
- `archive` (ArchiveConfig).

## Как пользователь выбирает реализацию
- Через `ClientConfig`: `archive` (ArchiveConfig).
- Через DI: прямое внедрение `TempDirectoryProviderInterface` в `ArchiveConfig`.
- `auto`: если Spatie доступен — используем его, иначе fallback на native.
- `spatie` без установленного пакета → `ConfigurationException`.

## Логика работы (текстовое описание)
1) При первом обращении к архиву определяется драйвер (DI → config → fallback).
2) Определяется temp‑директория (из драйвера или из `ArchiveConfig::tempDir`).
3) Создаётся временный файл и **сразу** фиксируется его путь для последующей очистки.
4) Контент архива записывается в temp‑файл.
5) В зависимости от формата открывается `ZipArchive` или `PharData`.
6) Выполняются операции чтения, стриминга и извлечения.
7) При любой ошибке после создания temp‑файла выполняется немедленная очистка.
8) При успешной работе temp‑файл остаётся доступным до конца жизненного цикла объекта.
9) Финальная очистка выполняется явным cleanup и дублируется в `__destruct()` как страховка.

## Поведение по ошибкам и гарантия очистки
- Ошибка создания temp‑файла, записи, открытия архива — `ConfigurationException`.
- Для `spatie` при отсутствии пакета — `ConfigurationException`.
- При исключении в процессе работы temp‑файл удаляется сразу, в том же контексте.
- Если удаление не удалось, это рассматривается как ошибка конфигурации/окружения.
- `__destruct()` остаётся как fallback и не является основным механизмом очистки.

## Нюансы и ограничения
- «Без temp файлов» невозможно для ZIP/TAR без внешней библиотеки.
- Temp‑директория должна быть доступна для записи; иначе выбрасывается `ConfigurationException`.
- Temp‑файлы не решают проблему больших архивов в памяти — это отдельный риск.

## План реализации (технические детали)
1) Конфигурация:
   - `packages/brahmic/apisutra/src/Config/Config.php`:
     добавить `ArchiveConfig` и опциональный `ClientConfig::$archive`.
   - Обновить `ClientConfig::with()` с передачей новых значений.
2) Контракт и драйверы:
   - Ввести `TempDirectoryProviderInterface` в `packages/brahmic/apisutra/src/Extensions/Archive`.
   - Реализации:
    - `NativeTempDirectoryProvider` (использует `sys_get_temp_dir()` или `ArchiveConfig::tempDir`).
     - `SpatieTempDirectoryProvider` (использует `spatie/temporary-directory`).
   - Резолвер драйвера: `ArchiveTempDriverResolver` (логика `native`/`spatie`/`auto` и проверка доступности Spatie).
3) Внутренний менеджер temp‑файлов:
   - `ArchiveTempFileManager` — единая точка создания/очистки.
   - Ответственность: создание файла, суффикс, запись контента, строгая очистка, обработка ошибок.
4) `ArchiveResponse`:
   - Расширить конструктор: принимать `ClientConfig` (nullable) и/или провайдер.
   - Использовать `ArchiveTempFileManager` для создания temp‑файла и строгой очистки при ошибках.
   - Оборачивать открытие архива в `try/catch` с немедленной очисткой.
   - Убрать `@unlink`, заменить на централизованный cleanup.
5) `ArchiveResponseHandler`:
   - В `handle()` передавать `$context->config` и/или провайдер в `ArchiveResponse`.
6) `FileResponse` и pipeline:
   - Добавить опциональный `ClientConfig` в `FileResponse`.
   - В `Pipeline::makeFileResponse()` передавать `$this->config`.
   - В `FileResponse::asArchive()` прокидывать конфиг дальше.
7) Проверка расширений:
   - `ArchiveExtension::checkDependencies()` — не отключать расширение, если доступен хотя бы один из `ext-zip` или `ext-phar`.
   - В `ArchiveResponse` явно проверять наличие нужного расширения под формат.
8) Минимальные проверки:
   - Добавить тесты на очистку temp‑файлов при ошибке создания/открытия (если будет тестовый контур в пакете).
