# Вопрос: источник данных для RequestFactory

## Предварительный анализ кода (текущее состояние)
- Архитектурный контракт `RequestFactoryInterface` принимает только `Illuminate\Http\Request`.
- Реализация `Laravel\RequestFactory` уже поддерживает `Request|array` (контравариантно), но интерфейс и архитектура это не отражают.
- В режиме `array` сейчас:
  - `route` всегда пустой → path‑параметры не заполняются.
  - `headers` и `files` не поддерживаются (всегда пустые).
  - `query/body` заполняются одинаково одним массивом.
  - HTTP‑method берётся только из атрибутов запроса (`#[Get]`, `#[Post]` и т.п.).

## Несоответствие документации
- `docs/features/laravel-integration.md` описывает `make(string $requestClass, array $source = [])`.
- `docs/architecture/01-contracts.md` фиксирует `make(string $requestClass, Request $httpRequest)`.

## Влияние на бизнес-логику
- CLI/тесты без HTTP‑Request требуют массивы → ожидается поддержка.
- Сейчас режим массива частично функционален и может приводить к тихим ошибкам
  (например, незаполненные path‑параметры).

## Ответы (предлагаемые)
1) **Официально поддерживать `array`?**  
   **Ответ:** да, как дополнительный источник данных для CLI/тестов.  
   **Аргументы:** реализация уже принимает `array`, а документация подразумевает этот режим.

2) **Фабрика строго Laravel‑специфична?**  
   **Ответ:** остаётся Laravel‑специфичной, но поддерживает «data‑mode» через массив.  
   **Аргументы:** не требуется отдельный сервис, достаточно расширить контракт.

3) **Нужен отдельный контракт?**  
   **Ответ:** не обязателен; проще расширить текущий интерфейс до `Request|array`.  
   **Аргументы:** минимизирует число сущностей и совпадает с текущей реализацией.

## Что сделать и в каком порядке
1) Обновить контракт `RequestFactoryInterface` до `Request|array`.
2) Синхронизировать `docs/architecture/01-contracts.md` и `docs/features/laravel-integration.md`.
3) Улучшить режим массива: поддержать **структурированный формат**:
   - `['route' => [], 'query' => [], 'body' => [], 'headers' => [], 'files' => []]`.
   - Если структура не задана — использовать текущий упрощённый режим (`query = body = source`).
4) Расширить обработку `files`: принимать `FileInput`, `UploadedFile`, массивы этих типов.

## Риски
- Изменение контракта может затронуть внешние реализации интерфейса.
- Без поддержки `route/headers/files` режим массива остаётся неполным.
- В режиме массива нельзя переопределить HTTP‑method (он идёт из атрибутов запроса).
- Для POST‑запросов параметры из `query` попадают только если есть `#[Query]`.
