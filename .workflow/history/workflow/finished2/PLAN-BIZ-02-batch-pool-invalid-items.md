# План: обработка неподдерживаемых элементов в batch/pool

## Цель
Определить и закрепить поведение при передаче некорректных элементов в `batch()` и `pool()`.

## Контекст
Сейчас:
- `BatchExecutor::resolveRequests()` и `PoolExecutor::normalizeRequests()` **молча пропускают** элементы, которые не являются `RequestInterface`/`callable`/`class-string`.
Это может приводить к «тихой» потере запросов без ошибок.

## Вопрос для согласования
Какое поведение выбрать:
1) **Fail‑fast:** выбрасывать `ConfigurationException` при первом неподдерживаемом элементе.
2) **Silent skip:** сохранять текущую логику, но явно документировать.
3) **Warn + skip:** логировать предупреждение (если logger есть), продолжать выполнение.

## Рекомендация
Вариант **1 (Fail‑fast)** — снижает риск скрытых ошибок и совпадает с ожиданием типизированной коллекции.

## Шаги
1) Утвердить вариант поведения.
2) Реализовать в `BatchExecutor` и `PoolExecutor` единый контроль входных элементов.
3) Обновить документацию (`docs/features/batch.md`, `docs/features/overview.md`, `docs/glossary.md` при необходимости).
4) Добавить тесты на неверный тип элемента.

## Критерии приёмки
- Поведение едино для batch/pool и документировано.
- Некорректные элементы обрабатываются предсказуемо.

## Риски
- Вариант Fail‑fast может быть несовместим с существующим «мягким» использованием.
