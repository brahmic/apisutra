Приоритет означает важность для проектирования, а не срочность исправления дефекта.

| ID | Приоритет / вид | Основание и последствие | Проверка / действие |
| --- | --- | --- | --- |
| N1 | P1, наблюдение | [TimeoutResolver](../../../src/Pipeline/Preparation/TimeoutResolver.php): runtime → атрибут → конфиг. Default в админке не означает обязательный потолок | Разделить defaults и ограничения; существующие timeout-тесты подтверждают overrides |
| N2 | P1, наблюдение | [RetryConfigResolver](../../../src/Pipeline/Transport/RetryConfigResolver.php): runtime меняет attempts поверх атрибута; поля Retry-атрибута имеют собственные defaults. Auth retry учитывается отдельно от ordinary attempts | Не заменять это произвольным merge. Явно назвать область лимита обычных попыток и отдельно auth; проверить независимость budget и withoutRetry |
| N3 | P1, наблюдение | [RequestFlowRunner](../../../src/Pipeline/Flow/RequestFlowRunner.php): cache preparation → стадия BeforeSend → auth → hook BeforeSend. ## Вопросы

Вопросы адресованы владельцу продукта. Направление внутренней декомпозиции,
необязательный допуск и zero-config уже поддержаны; повторного согласования не требуют.

| ID / статус | Что требуется выбрать | Рекомендация и продуктовое последствие | Что зависит |
| --- | --- | --- | --- |
| В1 / открыт | Означает ли пауза запрет нового SDK-выполнения, включая cache hit? | Да. Операция возвращает локальный отказ даже при наличии кеша; показ сохранённых данных решает приложение | 023: точка допуска и тесты кеша |
| В2 / открыт | Отдельно: ошибка допуска и ошибка policy provider | В обоих случаях SDK не отправляет запрос. Без provider клиент не затронут; приложение может явно вернуть допустимую резервную policy. Пустая policy снимает динамические caps и не является универсальной рекомендацией | 023/024: доставка ошибок |
| В3 / открыт | Какие начатые операции продолжаются после паузы/смены политики? | Один send с автопагинацией, его retry и связанные вызовы того же клиента продолжаются. Новый элемент внешнего batch/pool и каждый новый poll проверяются заново; другое подключение проверяется отдельно | 023/024: область выполнения |
| В4 / открыт | Первая поставка политик и сила её ограничений | Таймауты/бюджет, ordinary retry и диагностика. Defaults переопределяемы; явно заданные потолки обойти атрибутом/runtime нельзя. Cache/rate/pool/maxPages пока сохраняют текущую конфигурацию | 024: объём и приоритеты |

Техническая рекомендация для допуска — один типизированный интерфейс и готовый
адаптер callback, без реестра обработчиков; отдельного выбора класса для каждого
простой проверки не требуется. Доставка: существующий `execution_error` с устойчивым
`reason`, без нового значения enum и фиктивного HTTP-статуса. Подробности в контракте.

После рецензии причины именуются небольшим ExecutionControlReason: string;
«без нового значения enum» выше относится к существующему ErrorCode.
Ответы коллеги учтены как рекомендации, вопросы владельцу остаются открытыми.

## Выводы

Сборщик — самостоятельный внутренний рефакторинг без продуктовых изменений.
Пауза — небольшая функция по публичному API, но затрагивает границы выполнения
и обработку ошибок; реализация одним BeforeSend callback не подходит.
Динамические политики — наиболее широкая задача: она требует согласованного чтения
настроек несколькими сервисами, а не только группировки параметров конструктора.

Подготовка завершена. При рецензии 2026-09-13 предлагался порядок
**023 → 024 → 022** (ранее 022 → 023 → 024); после поручения об отложении
активной очереди реализации нет. Все планы имеют статус `отложен` в backlog.
При востребованности уточнить цену и объём динамики, открытые В1–В4 и порядок работ.
022 не зависит от ответов В1–В4. Новые runtime-зависимости, Laravel, БД, обязательные
идентификаторы подключения и административная UI в предлагаемый объём не входят.

Внутри 024 — таймауты/budget → ordinary retry → диагностика. Дополнены обязательные
проверки происхождения parent, сохранности handlers через with/fromLaravel, диагностики
отказа и времени источника. Исправлено обещание немедленной очистки scope после break:
сохранённый generator остаётся приостановленным, что подтверждено отдельной PHP-пробой.
Новый режим fallback, SDK-кеш policy и будущая отмена между страницами не добавляются.
