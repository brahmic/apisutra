# Разработка ApiSutra

Этот маршрут предназначен для изменения самого `brahmic/apisutra`: src, тестов,
зависимостей, CI, документации и выпуска. Для создания SDK внешнего API используйте
[пользовательский маршрут](docs/start/create-sdk.md).

## Подготовить checkout

Нужны Git, PHP 8.4+ и Composer. Из корня репозитория:

```bash
composer install
composer test
```

Обычные тесты используют локальные зависимости; внешнее приложение и база данных
им не нужны. Отдельные Laravel/Redis-проверки имеют свой стенд.

Перед изменением выберите инструкции в [указателе правил](.agents/README.md).
Для ИИ-агента действуют [AGENTS.md](AGENTS.md) и те же правила checkout.
Пользовательская agent-страница не заменяет инструкции разработчика пакета.

## Подготовить изменение к проверке

Зафиксируйте наблюдаемую проблему и ожидаемый контракт. Общий механизм остаётся
в ApiSutra; особенности API конкретного провайдера — в его SDK. При изменении
поведения добавьте проверку затронутого сценария и обновите его единственного
владельца в [справочнике](docs/reference/README.md). Объясните совместимость и
действия миграции. Планы, аудиты и ADR ведутся по [workflow](.workflow/README.md).

Проверки выбираются по области изменения; команды и отдельные окружения описаны
в [testing](development/testing.md). Прежде чем считать документационное изменение
готовым, проверьте ссылки, декларации, опубликованные примеры и поставку.

## Поставка

Пользовательские README, docs и примеры входят в Git/Composer архивы. CONTRIBUTING,
`development/`, `.agents/`, `.workflow/` и тестовый стенд доступны в checkout и
исключены из архивов. Поэтому из публичных страниц ссылка на разработку использует
полный URL репозитория. `composer check-package` проверяет фактический состав,
установку без require-dev и standalone smoke обоих архивов.
