# Миграция v0.5.0-alpha.1

При обновлении с v0.4.0-alpha.1 перенесите подключение и параметры в единый
`ClientConfig::cacheConfig`. Это несовместимое изменение API.

## Подключение

**До:**

```php
$config = new ClientConfig(baseUrl: $url, cacheStore: $store, cacheConfig: new CacheConfig(ttl: 60));
```

**После:**

```php
$cache = new CacheConfig(store: $store, ttl: 60);
$config = new ClientConfig(baseUrl: $url, cacheConfig: $cache);
$copy = $config->with(timeout: 7); // Блок и хранилище сохранены.
$short = $config->with(cacheConfig: $cache->with(ttl: 10));
```

Если уже есть готовый блок, передайте `$params->with(store: $store)`;
для nullable блока — `($params ?? new CacheConfig())->with(store: $store)`.
Обновите SDK-фабрики, named arguments, массивы для unpacking/fromLaravel и чтение
`$config->cacheStore` на `$config->cacheConfig?->store`.
Аргументы `cacheStore:` и прежний `cache:` больше не принимаются, включая null,
и дают PHP Error. Backend вместо CacheConfig или неверный store даёт TypeError.

## Полная и частичная замена

| Было в 0.4 | Стало в 0.5 |
| --- | --- |
| `with(cacheConfig: new CacheConfig(ttl: 10))` сохранял store | Полная замена; новый блок без store отключит подключение. Для изменения TTL используйте `$cache->with(ttl: 10)` |
| `with(cacheStore: $other)` | `with(cacheConfig: $cache->with(store: $other))` |
| `with(cacheStore: null)` сохранял параметры | `with(cacheConfig: $cache->with(store: null))` |
| `with(cacheConfig: null)` сбрасывал параметры и сохранял store | Теперь удаляет весь блок. Для прежнего эффекта передайте `new CacheConfig(store: $cache->store)` |
| `with(cacheStore: null, cacheConfig: null)` | `with(cacheConfig: null)` |

В примерах `$cache` — текущий непустой блок. `CacheConfig::with()` сохраняет
непереданные поля; null допустим для store, identity и locks. Сброс store сохраняет
явный locks provider, удаление блока снимает его. Отключение только HTTP по-прежнему
задаётся mode Disabled или withoutCache(); auth использует сохранённый store.

## Позиционные вызовы и данные

В ClientConfig удалён девятый аргумент cacheStore: cacheConfig и последующие
аргументы сдвинулись на одну позицию влево. Переведите такие вызовы на именованные.
У CacheConfig store добавлен шестым, после locks; прежние пять позиций сохранены.

Копирование не очищает backend и не меняет исходный клиент. Ключи, формат записей,
TTL существующих данных, identity и правила блокировок не меняются. Перенос данных
или очистка при миграции не нужны. Подробный [контракт](../reference/execution/cache.md#копирование-и-отключение).
