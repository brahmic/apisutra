# Миграция на v0.2.0-alpha.1

Выпуск `v0.2.0-alpha.1` меняет поведение `v0.1.0-alpha.1` в перечисленных сценариях.
Обновление не полностью обратно совместимо. Проверьте строки, относящиеся к вашему
SDK; обязательных префиксов, RedactionPolicy или нового конфигурационного файла нет.

## После v0.2.0-alpha.1: ожидание и кеш метаданных

Эти исправления действуют и без внешнего набора правил:

- `await()` больше не определяет готовность успешной гидратацией DTO. Укажите
  `ContinuationResult::stateResolver`, непустой `unwrap` или клиентский
  `continuationStateResolver`; без критерия будет ошибка конфигурации до polling.
  Ошибка финального DTO завершает ожидание сразу. Для `awaitByTokenAs()` нужен
  клиентский resolver. При ручном создании `ContinuationService` передайте гидратор
  вторым аргументом. Порядок перехода и обработка исключений — в
  [миграции ожидания](provider-async-await.md#миграция-с-эвристического-ожидания).
- Объектные defaults конструктора и аргументы атрибутов больше не разделяются
  между DTO и запросами из-за кеша. Не используйте их как общее изменяемое состояние.
  Scalar/enum defaults и намеренно переданные общие объекты сохраняют поведение.
  Момент вычисления описан для [defaults](dto.md#значения-по-умолчанию-и-изоляция-объектов)
  и [аргументов Cast](casts.md).

## После v0.2.0-alpha.1: внешние правила DTO

Новый `ClientConfig::hydrationRules` включается явно. Без набора действуют прежние
правила после исправлений metadata cache и continuation. Для переноса plain-моделей,
отказа от неявных scalar conversions и сохранения неизвестных полей см.
[переход существующего SDK](hydration-rules.md#переход-существующего-sdk).
Набор исключает объявленный receiver из запросов клиента, а `DTO::from()` и `toArray()`
не наследуют его автоматически.

## Транспорт, форматы ответа и дедлайн

- Guzzle/cURL 55/56 теперь дают `connection_failed` / ConnectionException вместо
  `invalid_request`. Они участвуют в уже разрешённом сетевом retry: это касается
  и POST с ранее указанным `safe: true`. Пересмотрите обработку кодов и разрешения
  safety для операций с побочными эффектами. Диагностика
  [состояния отправки](errors.md#состояние-отправки) не доказывает отсутствие эффекта на сервере.
- Неизвестный явно указанный не-JSON Content-Type без DTO возвращает строку вместо
  `[]` или случайно декодированного JSON; с DTO/пагинацией без обработчика даёт
  `response_decoding_error`. Для специального декодирования используйте extension
  handler; для намеренного чтения строки — [RawResponse](attributes/response.md#rawresponse).
  Без Content-Type сохраняется строгий JSON.
- HTTP `RateLimitException::retryAfter` корректно читает HTTP-date. Неверные,
  отрицательные и непредставимые значения теперь null вместо 0/отрицательного числа.
  Корректные секунды и прошедшая дата сохраняют смысл, единица поля — секунды.
- [Внешний ExecutionDeadline](client-config/timeouts-delay.md#общий-дедлайн-нескольких-вызовов)
  и [условная safety](retries-rate-limit.md#условная-безопасность-запроса) опциональны.
  Без их применения отдельные send и политика безопасности работают по прежним
  правилам; дополнительных зависимостей и настроек ClientConfig нет.

## Зависимости и границы

Ядро по-прежнему устанавливается без Laravel, приложения и базы данных. PHPStan,
PHP_CodeSniffer и отдельное Laravel-приложение используются только при разработке.
Архив поставки содержит код и публичную документацию; тесты и инструменты разработки
доступны в исходном репозитории.

Promise-интерфейс сохранён, но штатный Guzzle-адаптер выполняет HTTP синхронно.
Режим Parallel сам по себе не гарантирует одновременный I/O. PSR-16 store позволяет
делить счётчик лимитов, но не обещает строгую атомарную квоту между процессами.
Планировщик очереди запросов находится в ведении приложения.

Для собственного транспорта проверьте capability-контракты таймаутов, готовых URL
и streaming только для используемых возможностей. Существующие публичные интерфейсы,
хуки, casts, authenticators и extensions остаются точками расширения; массового
перевода их в internal нет. [Подключение транспорта](transport.md).
