# Правила документации

## Когда применять

При изменении `README.md`, `docs/`, публичных примеров в `docs/example/` и файлов
инструкций. Правила оформления примеров ниже относятся к документации;
тестовые фикстуры проверяются по требованиям конкретного теста.

## Обязательно

- Сохраняйте назначение разделов: `docs/guides/` — практические инструкции,
  `docs/guides/client-config/` и `docs/guides/attributes/` — полные справочники,
  `docs/technical/` — архитектурные обзоры, `docs/glossary/` — определения.
  Внутренние аудиты, планы и обсуждения храните в `.workflow/`
  по [отдельным правилам](../.workflow/README.md).
- При добавлении или перемещении гайда обновляйте [общий индекс](../docs/README.md),
  [индекс гайдов](../docs/guides/README.md) и затронутые ссылки.
- Проверяйте имена классов, методов, атрибутов, настройки и поведение по текущим
  `src/` и тестам. Обнаруженное расхождение исправляйте в профильном руководстве.
- Полную спецификацию поддерживайте в одном профильном разделе. В остальных
  местах оставляйте краткое пояснение и относительную ссылку.
- В PHP-примерах используйте именованные классы, импорты `use` и русские
  комментарии. Анонимные классы и полные имена классов внутри выражений не используйте.
- Используйте термины из [глоссария](../docs/glossary/README.md): «провайдер»,
  «ресурс», «SDK-клиент», «транспорт». Сохраняйте написание `ClientConfig`, `DTO`,
  `rate-limit`, `auto-discovery`, `auto-resolve`.

## Проверка точности по теме

- Для query и JSON различайте способы кодирования: `QueryArrayFormat` задаёт
  формат массивов в query string; JSON-строка в отдельном поле требует `JsonCast`
  или явно сформированной строки. См. [сериализацию](../docs/guides/serialization.md).
- Различайте гидрацию DTO, их DX-сериализацию и формат исходящего запроса.
  Политики и приоритеты описаны в [настройках сериализации](../docs/guides/client-config/serialization.md).
- Для работы без Laravel отдельно указывайте зависимости автоматического
  разрешения клиентов, валидации и транспорта. Контейнер опционален; для проверки
  правил `#[Validate]` встроенному валидатору нужна фабрика, которую можно передать
  через `Validator::useFactory()`. См. [контейнер](../docs/guides/client-config/container-provider.md),
  [валидацию](../docs/guides/validation.md) и [Laravel-интеграцию](../docs/guides/laravel.md).
- При описании конкретного SDK дополнительно применяйте [правила провайдеров](providers.md).

## Рекомендации

- Делайте пример минимальным, но достаточным для воспроизведения описанного сценария.
- Предпочитайте `final readonly` для конечных DTO в примерах; базовые DTO,
  предназначенные для наследования, оставляйте расширяемыми.
- Начинайте гайд с практического действия, а детали связывайте со справочником.
