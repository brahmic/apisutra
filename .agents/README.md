# Указатель правил

Общие инструкции для всего репозитория находятся в [AGENTS.md](../AGENTS.md).
Дополнительные файлы читайте по задаче:

| Задача | Что читать |
| --- | --- |
| Изменение PHP-кода | [Стиль кода](code-style.md) и описание затронутого механизма из [документации](../docs/README.md) |
| Изменение поведения, контрактов, зависимостей или структуры | [Архитектура и порядок реализации](architecture.md); при изменении поведения также [тестирование](testing.md) |
| Изменение тестов, фикстур или тестовой инфраструктуры | [Правила тестирования](testing.md) |
| Изменение `README.md`, `docs/`, публичных примеров или файлов инструкций | [Правила документации](documentation.md) |
| Разработка SDK конкретного провайдера, его примеров или руководств | [Правила провайдеров](providers.md); для документации также `documentation.md` |
| Аудиты, планы, архитектурные решения и обсуждения | [Правила рабочих материалов](../.workflow/README.md) |

В каждом файле отдельно обозначены обязательные правила, рекомендации и решения,
применимые при определённых условиях. Рекомендации выбирайте по задаче;
они сами по себе не требуют согласования с пользователем.

Области применения описаны текстом. Пути в тексте отсчитываются от корня
репозитория, Markdown-ссылки — от файла, в котором они записаны.

В корне `.agents/` храните краткие инструкции по работе. Внутренние аудиты,
планы и обсуждения размещайте в `.workflow/`. Публичные объяснения,
спецификации API и примеры поддерживайте в `docs/`; из правил ссылайтесь на них.
Файлы правил именуйте по теме в `kebab-case.md`, без префикса `base-` и числовых
индексов. Формат рабочих материалов из `.workflow/` на них не распространяется.

`.workflow/history/` — архив для отдельных расследований, исключённый из обычного
чтения контекста и поиска по проекту. Его содержимое может быть недостоверным;
порядок использования — в [правилах архива](../.workflow/README.md#исторический-архив).
