# Changelog

## Не выпущено

### 2026-09-12 — безопасные повторы и восстановление потоков

- Добавлена опциональная RetryConfig.safeMethods: по умолчанию GET/PUT/DELETE.
  POST/PATCH требуют явного разрешения в конфиге клиента или `#[Retry(safe: true)]`.
  Атрибут safe перекрывает конфиг; отсутствие safe и null равнозначны. Новые
  обязательные настройки не нужны, общие retry по умолчанию выключены.
- Проверки безопасности и тела применяются к HTTP, сетевым, управляющим и auth-повторам.
  `RetryableException` не обходит выключенный retry и лимит попыток; auth retry
  сохраняет отдельное включение и лимит.
- Seekable-тела автоматически восстанавливаются к исходной позиции. Multipart
  сохраняет байты и позиции вложенных файлов, включая ненулевую позицию и пустой файл.
  При невозможном повторе сохраняется исходная ошибка и retryRefusalReason в её контексте.
- Встроенный backoff больше не задерживает первую попытку. Retry-After для 429/503
  объединяется с backoff через максимум; ожидание использует SleeperInterface.
- `#[Retry(enabled: false)]` учитывается; runtime overrides сохраняют totalTimeoutMs,
  retryExceptions и safeMethods. Полноценный deadline и транспортные таймауты остаются
  отдельным этапом; ограничения описаны в документации.
- Автоматический ключ идемпотентности создаётся без вызова отсутствующего request.toArray().
  Он стабилен внутри выполнения и различается между независимыми выполнениями;
  ключ пользователя, включая явно переданный заголовок, сохраняется.
- Проверено: 942 теста без падений (904 passed, 38 с прежними deprecation), 2712 assertions;
  standalone retry smoke без Laravel/Guzzle HTTP Client. Версия и зависимости не менялись.

### 2026-09-12 — строгий JSON и классификация ошибок

- Ошибки исходящего JSON возвращают `serialization_error` до HTTP-вызова;
  JsonCast, JSON-поля multipart и Base64 больше не подставляют false/пустое тело.
- Непустой malformed JSON с JSON Content-Type или без Content-Type даёт `response_decoding_error`
  с сохранением HTTP-ответа и исходного JsonException.
- PSR-18 ошибки нормализуются до retry; произвольные Throwable не превращаются
  в ошибки соединения. Сохраняются исходные причины и явные retryExceptions.
- Последний HTTP-ответ сохраняет свою классификацию после повторов. Для
  немаппируемых 4xx добавлен `client_error`, для 400 — `bad_request`.
- Ошибки hooks и гидратации различаются; EarlyReturn после AfterResponse
  больше не ошибочно превращается в сетевой сбой.
- Изменён контракт успеха без DTO: JSON `null`, пустое тело и HTTP 204 дают `null`;
  `text/plain` сохраняет исходную строку, скаляры JSON — своё значение. Непустой
  ответ без Content-Type считается JSON. Array-only `BeforeHydrate` пропускается
  для null/скаляров/текста; download, handlers расширений и DTO сохраняют отдельную обработку.
- Проверено: 875 тестов без падений, 38 с deprecation;
  standalone JSON smoke работает без Laravel и Guzzle HTTP Client.

### 2026-09-12 — изоляция кеша, auth scope и безопасная диагностика

Первая поставка выбранных частей AS-04/09/10 с автоматической identity кеша.
Версия пакета не изменена.

#### Изменения совместимости

- HTTP-кеш автоматически определяет пространство по SDK-клиенту, baseUrl и auth
  identity. `prefix` и `withCacheScope()` необязательны и служат дополнительному
  разделению; одинаковая метка не объединяет разные учётные записи.
- Добавлен `CacheIdentityProviderInterface`: встроенные authenticators поддерживают
  его автоматически; собственные authenticators и SDK с отдельным tenant объявляют
  контекст через этот контракт. Неизвестная identity пропускает HTTP-кеш.
- Custom key сохраняет объединение обычных вариантов запроса внутри identity/tenant.
  Контракт учитывает credentials и tenant после hooks; встроенные authenticators
  поддерживают также свои нестандартные header/query credential-поля.
- Автоматическое кеширование ограничено безопасными методами. Для POST, PUT,
  PATCH и DELETE нужно явно включить кеширование атрибутом или runtime-опцией.
- `clearCache()` очищает пространство SDK-клиента без глобального сброса общего
  хранилища и работает без `prefix`. Учитываются настроенные auth identities и
  tenant-контекст. Очистка запроса инвалидирует его группу в соответствующем пространстве.
- Формат ключей HTTP-кеша изменён: используются SHA-256 и поколения инвалидации.
  Старые записи не читаются и остаются в хранилище до истечения их TTL.
- Recorder применяет базовую маскировку секретов даже без `#[Fixture]`.

#### Исправлено

- Автоматический ключ учитывает фактически подготовленные URI, тело и заголовки.
  Явный `#[Cache(key: 'name')]` сохраняет объединение запросов под одним ключом
  внутри выбранного пространства identity/tenant.
- Попадание в кеш больше не продлевает TTL. Инвалидация препятствует записи
  результата выполнения, начатого до очистки; сохранены режимы чтения и записи.
- `withAuth()`, `withoutAuth()` и `forceAuth()` сбрасывают прежний runtime auth scope,
  сохраняя приоритеты атрибутов и независимость execution-копий.
- Единая расширяемая `RedactionPolicy` маскирует известные секреты в безопасной
  диагностике результата, штатном logger и recorder, включая URL, заголовки и
  структурированные тела. Политика применяется по умолчанию; явно передавать
  `ClientConfig::redaction` нужно только для дополнительных правил провайдера.
  Исходные данные и потоки не изменяются; raw-доступ остаётся явным и не гарантирует
  маскировку.
